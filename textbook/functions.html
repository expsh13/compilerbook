値の置き場と、処理の行き先を作る

関数と
ローカル変数

名前の付いた値を残す。条件で進む道を変える。
関数を呼び、その関数だけの作業場所を使って戻る。

この章の到達点変数の読み書きと関数呼び出しを、RBP・RSP・メモリの変化で説明できる。

「分割コンパイルとリンク」に続く、原書のステップ９〜15に対応。Linux・x86-64・Intel記法。説明・図・コードは独自の学習用例。

01変数の名前を、置き場につなぐ

第２章の計算結果は、その場で消費していた。変数を足すと、あとで読める場所に値を残す必要がある。まずは各変数に８バイトの置き場を用意し、名前と置き場を対応させよう。

これから扱う自作言語の例：add(8, 5) は13を返す
add(a, b) {
    total = a + b;
    return total;
}
main() {
    return add(8, 5);
}

この段階の自作言語では、型を書かずに変数を使う。上の例は現代のCとしてそのままコンパイルするコードではない。本章の説明では、引数もローカル変数も８バイトの整数として扱う。

RBPは置き場を探す基準、RSPは今のスタックの先頭

total の位置を RBP - 24 と決めておく。途中計算で push してRSPが動いても、同じ関数の処理中はRBPを固定しておけば、totalを見失わない。

これは学習用コンパイラで採る配置。最適化するコンパイラなら、値をレジスタだけに置いたり、変数自体をなくしたりできる。「ローカル変数は必ずメモリにある」という言語上の決まりではない。

関連：LLVM公式教材の変数と読み書き。

02置き場と中身を区別する

代入では、左のtotalと右のaで欲しいものが違う
total = a + 5;

左側では「totalの置き場」、右側では「aに入っている値」を求める。どちらも変数のノードだが、使われ方に応じて生成する命令が違う。

上の式に対応する、読みやすく整理した命令例
lea rdi, [rbp - 24]     # totalのアドレス
mov rax, [rbp - 8]      # aの中身を読む
add rax, 5
mov [rdi], rax          # totalの置き場へ書く

lea はアドレスを計算する。mov rax, [rbp - 8] は、そのアドレスから８バイト読む。角カッコがあっても、leaはメモリの中身を読まない。

値の置き場を指定する式を左辺値という。代入先には変更できる左辺値が必要で、a + 1 = 7 は書き込み先を表さないためエラーにする。左辺値は「左にしか書けない式」という意味ではなく、右側の a も置き場を持ち、値として使うときに中身を読む。

第２章の「式は値を１個積む」とつなぐ

代入式も値を持つ。a = b = 7 は a = (b = 7) と読み、bに保存した７を外側の代入へ渡す。

スタック方式での代入コード生成：考え方
左辺のアドレスを求め、積む
右辺の値を求め、積む
値を取り出す
アドレスを取り出す
そのアドレスへ値を保存する
保存した値をもう一度積む

参照：GNU C：代入式と左辺値。

03名前と構文木をつなぐ

１つの識別子として読む名前
total = subtotal + 5;

トークナイザは total を１個の識別子にする。英字・アンダースコアで始まり、その後に英数字・アンダースコアが続く、という読み取り規則を用意する。return_value をキーワードのreturnと残りに分けないよう、名前を最後まで読んでからキーワードと照合するとわかりやすい。

パーサは関数ごとに「名前 → オフセット」の表を持つ。同じ名前なら同じ枠を使い、新しい名前なら枠を１つ追加する。関数が変わったら、その関数の表へ切り替える。

名前オフセット実行時の置き場
a8RBP − 8
b16RBP − 16
total24RBP − 24

この表はコンパイル中のデータ。実行時にCPUが表から変数名を検索するわけではない。ASTの変数ノードにオフセットを残し、そこから命令を出力する。

代入を追加する文法の要点（それ以外の規則は省略）
expr   = assign
assign = equality ("=" assign)?

右側でも assign を呼ぶ形だから、連続する代入は右側からまとまる。左側が書き込み可能かどうかは、ノードを調べて別途確認する。

「枠を割り当てた」と「値を初期化した」は別。RSPを減らしても、その領域が自動で０になるわけではない。読む前に値を代入しよう。

04文を並べ、returnで戻る

ブロックは複数の文をひとまとめにする
if (a > 0) {
    total = a + b;
    return total;
}
return 0;

式は値を求め、文は処理の順序を作る。式の後ろにセミコロンを付けた式文では、使わない計算結果を片付ける。ブロックは、中の文を順に実行する１つの文になる。

この教材で採るコード生成の約束
式を生成する  → スタックに値が１個増える
文を生成する  → 通常の出口では増減が０
式文          → 式を生成し、結果を１個取り出して捨てる
ブロック      → 中の文を順に生成する

この約束なら、ループを何周しても不要な値が積み上がらない。文まで値を残す設計も可能だが、その場合は呼び出す側が必ず片付ける必要がある。両方の方針を混ぜない。

returnは、値を用意してからフレームを片付ける

全returnを共通の出口へ集める例：addの中
# return total; に対応する部分
mov rax, [rbp - 24]
jmp .Lreturn_add

# ほかのreturnもここへ飛ばす
.Lreturn_add:
mov rsp, rbp
pop rbp
ret

mov rsp, rbp でローカル領域を使用範囲から外し、pop rbp で呼び出し元の基準位置を戻す。その後のretが戻り先を取り出す。retだけでは、自分で確保したローカル領域を片付けてくれない。

returnより後に命令を出力してあっても、その経路では実行しない。{ } で文をまとめる機能と、同名変数を隠すブロックスコープの管理は別の機能として考えよう。

参照：GNU C：文・ブロック・return。

05分岐とループをジャンプにする

ループの独自例：１・２・３・４を足して10にする
total = 0;
for (i = 1; i <= 4; i = i + 1) {
    total = total + i;
}
return total;

CPUがfor文を直接実行するわけではない。コンパイラが条件を調べる命令とジャンプに置き換える。条件の値が０なら偽、０以外なら真として扱う。

ifのコード生成：条件式の値がスタックに１個ある状態から
pop rax
cmp rax, 0
je .Lelse_1
# 真の側の文
jmp .Lend_1
.Lelse_1:
# 偽の側の文
.Lend_1:

je は比較結果が等しいときに飛ぶ。この例では「条件が０なら偽の側へ」。入れ子でも飛び先が衝突しないよう、ラベルの番号は生成するたびに変える。elseを省略したifでは、偽ならそのまま終端へ飛ばす。

forの３つの式を省略したら？

初期化・更新がなければその処理を出さない。条件がなければ常に真とみなし、条件による終了判定を省く。この章の小さな言語ではbreakやcontinueはまだ扱わない。

参照：GNU C：for文。

06引数を渡して関数を呼ぶ

呼び出す側：RSPの整列を済ませた位置で、引数を用意する
mov rdi, 8
mov rsi, 5
call add
after_call:
# RAXに13が入っている

呼び出しは、引数を計算して渡すコードを作ること。定義は、名前のラベルと関数本体のコードを作ること。別のコンパイラで作った関数とも呼び合うには、値の受け渡し方を合わせる必要がある。

呼び方の約束がABI

ここではLinuxのSystem V AMD64 ABIを前提に、64ビット整数の引数を扱う。最初の６個は RDI, RSI, RDX, RCX, R8, R9、単純な整数の返り値はRAXで渡す。７個以上の引数や浮動小数点は、この教材の対象外。

RBPのように呼び出された側が元に戻すレジスタと、RAX・RDIのように呼び出しで変わり得るレジスタがある。f() + g() を作るときは、fの結果をgのcallで失わない場所に退避する。

この整数だけの例では、callの直前のRSPを16の倍数にそろえる。式の途中で８バイトpushすると整列がずれるため、引数だけでなく一時値の数も数える。call後は追加した整列用の余白も元に戻す。可変長引数関数を呼ぶ場合には、ベクトル引数数をALへ設定するなど追加の約束もある。

参照：System V AMD64 ABI §3.2。Windowsのx64などは別の呼び出し規約。

呼び出しの構文と、定義の構文を分ける

式の中の add(8, 5) は呼び出しノードで、関数名と引数の式を持つ。一方、トップレベルの add(a, b) { ... } は関数の定義で、仮引数の名前・本体・ローカル領域の大きさを持つ。

関数定義を追加した段階の文法の要点
program  = function*
function = ident "(" (ident ("," ident)*)? ")" "{" stmt* "}"

# 式の一部として読む関数呼び出し
call     = ident "(" (assign ("," assign)*)? ")"

識別子の次が ( なら、式の中では関数呼び出しとして読む。各引数の式を評価してから所定のレジスタへ移し、callを出す。先に引数をRDIなどへ入れてしまうと、後の引数を計算する中の関数呼び出しで壊される場合があるため、一時値を退避してから渡す。

定義を読む側では、仮引数にもローカルな置き場を割り当てる。関数の入口に、RDIなどで受け取った値をその置き場へ保存する命令を出す。この教材のaddでは、aとbの２枠がそれに当たる。

再帰でも、同じ名前の変数がぶつからない

07フレームを作って、片付ける

最初の add(8, 5) を１命令ずつ追う。ローカル領域の24バイトに、整列用の８バイトを足して32バイト確保する。subで場所を確保し、movで値を保存するという違いに注目しよう。

呼び出される側：上の自作言語に対応する命令例
add:
    push rbp
    mov rbp, rsp
    sub rsp, 32
    mov [rbp - 8], rdi
    mov [rbp - 16], rsi
    mov rax, [rbp - 8]
    add rax, [rbp - 16]
    mov [rbp - 24], rax
    mov rax, [rbp - 24]
    mov rsp, rbp
    pop rbp
    ret

Intel記法。読みやすさのため、式の中間結果はレジスタで計算した。第２章のpush/popによる生成より短くしているが、変数の置き場と呼び出し規約は同じ。

関数フレームの変化を観察

開始時はRDI＝8、RSI＝5、RSP＝0x1000、RBP＝0x1040。アドレスは説明用の仮の値。

0 / 13

次に実行：call add

引数を用意済み。まだaddのためのフレームは作っていない。

ret後もRAXの13は残る。ローカル変数の置き場はもう使用範囲外で、次の呼び出しなどで上書きされる。ここで返すのはtotalの値であり、totalが置かれていた場所ではない。

08理解を確かめる

RSPだけで変数の位置を覚えてはいけない？

RSPからの距離を常に補正する設計もできる。この教材では、一時値のpush/popでRSPが変わっても固定の距離で変数を探せるよう、RBPを使う。

sub rsp, 32で、変数の値も０になる？

ならない。変わるのはRSP。値を初期化するには、その場所に書き込む命令が必要。

同じaでも、代入の左と右で何が違う？

左では書き込み先のアドレスを求める。右ではその場所から値を読む。変数を見つけるオフセットは同じでも、その後の処理が違う。

ループの本体で計算結果を毎回積みっぱなしにすると？

繰り返すたびRSPが低い方へ移動する。文を実行する前後で一時スタックの深さをそろえ、不要な結果を片付ける。

callは、引数やローカル変数を自動で保存する？

call自身が積むのは戻り先。引数を渡す命令、RBPを保存する命令、ローカル領域を確保する命令は、それぞれ別に出力する。

別のコンパイラで作った関数でも呼べる理由は？

呼び出し側と定義側が同じABIを守れば、引数や返り値の場所が一致する。リンクで名前が見つかることに加えて、機械語レベルの呼び方も合っている必要がある。

実装したら、境界を確かめる

確かめる入力・状況観察したいこと
a = b = 7; return a + b;14。代入の右結合と、代入式の値。
return 9; return 2;9。最初のreturnで戻る。
最初から偽のwhile本体を一度も実行しない。
if・whileを入れ子にするラベルが衝突せず、一時スタックも増えない。
f() + g()gを呼んでもfの結果を失わない。call前の整列も確認。
同じ関数を再帰呼び出し外側の引数や変数が、内側に上書きされない。

このページの操作は固定の命令列を追う学習モデルで、コンパイラやCPUのエミュレータではない。自分の実装では、生成したアセンブリを実際にリンク・実行するテストも行おう。
