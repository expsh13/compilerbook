ポインタと
文字列リテラル

アドレスを保存し、指した先を読む。
型が幅を決め、配列が並びを作り、終端ゼロが文字列の終わりを伝える。

この章の到達点ポインタ自身・配列本体・文字列のバイト列を描き分け、型に応じたアクセスを説明できる。

原書のステップ16〜28に対応。Linux・x86-64のLP64を前提に、int＝４、char＝１、ポインタ＝８バイトとして図解。命令はIntel記法。

コード例は機能を組み合わせた独自の例。原書の導入段階の一時的な制約と、通常のCの意味を区別して説明する。

01アドレスを値として持つ

アドレスを渡して、同じ変数を書き換える
int x;
int *p;
x = 13;
p = &x;
*p = 21;
return x;     // 21

&x はxのアドレスを求める。p はそのアドレスを値として持つ変数。*p は、pが指す先のオブジェクトを参照する式だ。p自身もメモリに置けば、pの置き場とpの中身は別のアドレスになる。

第４章の「代入先では置き場、右辺では中身」という考え方がそのまま使える。*p の値が欲しいときは、pの値を読んで、その指す先を読む。*p = 21 の左辺なら、pの値を読み、それを書き込み先のアドレスとして使う。

コード生成の役割を分ける：考え方
x の置き場を求める     → xのアドレス
&x の値を求める        → xのアドレス
*p の置き場を求める    → pに入っているアドレス
*p の値を求める        → pに入っているアドレスから読み込む

宣言の int *p; は「pはintへのポインタ」。式の *p は「pの指す先を参照する」。同じ記号でも、宣言と式で役割が違う。ポインタの型が合うだけでは参照できず、生存中の有効なオブジェクトを指していることも必要だ。

参照：GNU C：ポインタの参照。

02型で、読む幅と進む幅が決まる

この章からは型によって領域の大きさを変える。本教材はLinuxのx86-64（LP64）を想定し、int＝４バイト、char＝１バイト、オブジェクトへのポインタ＝８バイトとする。第４章の「すべて８バイト」という簡易モデルから一歩進める。

型が違うと、同じ＋１でも進むバイト数が違う
int a[3];
int *p;
p = a;
p = p + 1;    // 次のintへ：４バイト進む

char s[3];
char *q;
q = s;
q = q + 1;    // 次のcharへ：１バイト進む

宣言を読むときに、変数の名前・型・置き場を表へ登録する。以前のように初登場の名前へ自動で領域を作らず、宣言されていない変数を使ったらエラーにする。

コンパイラは p + i を、アドレスに i × sizeof(*p) バイトを足す計算へ変える。型は実行時にポインタへ添付される札ではなく、コンパイラが命令を選ぶための情報だ。

同じ配列内のポインタ同士を引くと、差はバイト数ではなく要素数になる。intへのポインタなら、アドレス差を４で割る。ポインタ同士の足し算は認めない。

sizeofは、値を読む前に型を調べる

この教材の環境でのサイズ
int x;
int *p;
sizeof x;     // 4
sizeof p;     // 8
sizeof *p;    // 4：pが指す先を実際に読むわけではない

ここで扱う固定サイズの型なら、sizeofをコンパイル時の定数へ置き換えられる。標準Cで結果の型は size_t。可変長配列などは別の扱いになるが、この自作言語にはまだ導入しない。

標準Cのポインタ加算は、同じ配列の要素間と末尾の１つ先までが基本。たまたま隣に置かれた別のローカル変数へ、加算で移動してよいという意味ではない。末尾の１つ先のポインタは作れるが、そこから値を読んだり書いたりはできない。

03配列本体とポインタを分ける

配列本体と、先頭を指すポインタを用意する
int a[3];
int *p;
a[0] = 11;
a[1] = 22;
a[2] = 33;
p = a;
return p[1];  // 22

a は３つのintを連続して置く配列本体。p はアドレス１つを保持するポインタ変数。p = a では、配列aが先頭要素へのポインタに変換され、そのアドレスをpに保存する。配列の12バイトをpへコピーするわけではない。

Cの添字 a[i] は *(a + i) と同じ意味。この形へ読み替えれば、ポインタ加算と参照の処理を再利用できる。

式意味・型この例
a（通常の式中）先頭要素へのポインタに変換int *
&a[0]先頭のintのアドレスint *
&a配列全体へのポインタint (*)[3]
sizeof a配列本体の大きさ12
sizeof pポインタ変数の大きさ８

sizeofと単項&では、配列を先頭要素へのポインタへ変換しない。&a と &a[0] は同じ開始位置を表すが型が違い、&a + 1 は配列１個分の12バイト先、&a[0] + 1 はint１個分の４バイト先になる。

配列は代入で丸ごとコピーできず、a = p とは書けない。また、関数の仮引数を int a[] と書くとポインタ型へ調整される。関数内のsizeofから呼び出し元の配列長は取り出せないため、必要なら長さも渡す。

参照：GNU C：ポインタと配列、C11委員会草案 §6.3.2.1・§6.5.3.2・§6.5.6。

04置き場と読み書きの幅を選ぶ

呼び出しをまたいで残る置き場を作る
int counter;

int next() {
    counter = counter + 1;
    return counter;
}

ローカル変数のアドレスは、その呼び出しのRBPから求めた。グローバル変数には、呼び出しごとに作り直さない置き場を用意し、シンボル名で参照する。上のcounterは静的記憶域を持ち、初期化式を書かなくても０から始まる。

コンパイラでは、名前をローカルの表で探し、見つからなければグローバルの表を探す。トップレベルでは名前の後の ( を見て関数かを判断する、という小さな先読みから始められる。

charを読むなら、１バイトだけ読む

ポインタの幅が８バイトでも、指した先がcharなら読むのは１バイト。intなら４バイト。型から読み書きの幅を選ぶよう、コード生成を変える。

RAXに書き込み先のアドレス、RDIに値がある例
mov [rax], dil    # charへの保存：１バイト
mov [rax], edi    # intへの保存：４バイト
mov [rax], rdi    # ポインタへの保存：８バイト

小さい値をレジスタ全体へ読む際は、第５章の符号拡張・ゼロ拡張が必要になる。movsx rax, byte ptr [rdi] は１バイトを符号拡張する。plain charが符号ありかどうかは実装に依存するので、自作言語の方針を決めておく。

x86-64ではALへの書き込みは残りのRAXをそのまま残す。EAXへの書き込みはRAXの上位32ビットを０にする。負の32ビット整数を64ビットへ広げたい場合は、別途符号拡張が必要だ。

05文字列は、終端付きのchar配列

ここまでの機能がつながる：文字列を関数へ渡す
char *s;
s = "OK";
printf("%s\n", s);

"OK" は、文字OとKに終端のゼロ１バイトを加えたchar配列を作る。式中では先頭要素へのポインタになり、そのアドレスをsへ保存できる。文字列全体が８バイトのポインタ変数に入るのではない。

文字列リテラルの配列は静的記憶域を持つ。通常は読み取り専用領域に置き、変更しない。Cでは文字列リテラルを書き換えると未定義動作になる。ローカルのchar配列へコピーした文字列とは、置き場も寿命も違う。

普通のCで、ポインタと文字配列を比べる
標準Cの比較例：初期化式の実装は次章で扱う
const char *p = "OK";
char buf[] = "OK";

sizeof p;       // 8：ポインタの大きさ
sizeof buf;     // 3：O・K・終端ゼロ
buf[0] = 'N';   // 配列の中身は変更できる

pは文字列リテラルの先頭を指す。bufには３バイト分の別の配列を作り、文字をコピーする。標準Cの文字列リテラルの型はchar配列だが、変更禁止なので、指す変数にはconst char *を使うと意図を示せる。

コンパイラは、文字列のデータと参照を出す

Linux・x86-64の出力例：データを用意してアドレスを渡す
.section .rodata
.Lmessage:
    .byte 79, 75, 0
.Lformat:
    .byte 37, 115, 10, 0    # %s・改行・終端
.text
    lea rdi, [rip + .Lformat]
    lea rsi, [rip + .Lmessage]
    xor eax, eax           # ベクトル引数は０個
    call printf            # この前にRSPの整列を済ませておく

各文字列へ衝突しないラベルを付け、式ではその先頭アドレスを求める。配列の位置を埋める作業は、第３章のリンクの話につながる。printf は可変長引数の関数なので、System V AMD64 ABIの呼び出し規約に従い、整数・ポインタだけならALを０にする。

トークナイザは引用符の中を読み、\n のようなエスケープを実際のバイトへ変換する。終端ゼロも追加する。"A\0B" の配列は４バイトだが、通常の文字列処理は最初のゼロで止まるので、表示されるのはAまで。

参照：GNU C：文字列定数・文字列と終端。

06ファイル・コメント・テストを整える

プログラムが長くなったら、コマンドライン引数にソースを直接書く代わりに、ファイルを読む。コンパイラ内部では、読み込んだバッファと各トークンの位置を対応させておく。

読み込み失敗や閉じていない文字列・コメントは、その位置を示して止める。末尾の改行がない入力も、バッファの終端を越えて読まないようにする。

エラーの位置を表示する例
sample.c:4: p = &;
                ^ ここには式が必要です

コメントは空白と同じ役割で読み飛ばす

// は改行または入力末尾まで、/* は最初の */ までを読み飛ばす。ブロックコメントは入れ子にしない。文字列の中の "//" はコメントではなく文字なので、文字列を読んでいる状態と区別する。

int/**/x; は int x; と同じ。コメントをソース文字列から単純に削除して intx; にしてはいけない。トークンの境界を保つ。

テストも、１本のCプログラムにまとめる

関数・比較・分岐・文字列が揃うと、テスト関数の返り値を期待値と比べ、失敗した式を表示できる。多くのテストを一度にコンパイル・リンクして実行すれば、毎回プロセスを起動する負担が減る。

自作言語の実行結果を、期待値と比較する考え方
check(21, pointer_write(), "ポインタ経由の代入");
check(22, array_second(), "配列の２番目");
check(0, string_terminator(), "文字列の終端");

checkのような補助関数を別のCコンパイラで作ってリンクする方法も使える。成功するプログラムの実行テストに加え、未宣言の変数や閉じていないコメントを正しく拒否するテストも残す。

07指す先と読む幅を動かす

int配列とchar配列を切り替え、p = a + i を観察する。アドレスを求めることと、そこから読むことを別の操作にしている。

ポインタとメモリの観察室

アドレスは説明用。同じ仮の番地を使って、２つの別々の配列を比較するモデル。

選んだ配列と、現在の式
int a[3];
a[0] = 11; a[1] = 22; a[2] = 33;
int *p;
p = a + 0;

アドレスを求めた段階。まだ*pを読んでいない。

charの３番目は配列の中にある終端ゼロなので読める。「末尾の１つ先」は配列の外なので読めない。この２つを比べてみよう。

08理解を確かめる

pと&pと*pの違いは？

pは保存したアドレス。&pはポインタ変数p自身の置き場のアドレス。*pはpが指す先のオブジェクトを参照する式。代入の左なら書き込み先、値として使えば読み込みになる。

ポインタが８バイトなら、p＋１も８バイト進む？

進む幅は指す先の型で決まる。この環境でint *なら４、char *なら１、int **なら８バイト。ポインタ自身を格納する８バイトとは区別する。

配列を渡すと、本体も関数にコピーされる？

通常は先頭要素へのポインタを渡す。本体は元の場所にあり、そのポインタ経由で変更すれば元の要素が変わる。長さも必要なら別に渡す。

文字列"OK"は何バイト？

ここで使うASCII互換の文字コードでは、O・K・終端ゼロで３バイト。文字数の２、配列サイズの３、先頭を指すポインタの８を分けて考える。

終端ゼロのアドレスは、配列の末尾の１つ先？

違う。"OK"の終端は３要素のうち３番目で、配列内。末尾の１つ先はその次のアドレスで、参照できない。

関数内のローカル配列のアドレスを返してよい？

関数を抜けるとその配列の寿命が終わる。メモリにバイトが残っていても、返したポインタで有効に使えるわけではない。静的記憶域を持つ文字列リテラルとは違う。

実装したら、境界を確かめる

確認するもの見たい結果
ポインタ経由の代入元の変数が変わる。ポインタの値は変わらない。
intとcharの添字アクセス型ごとの幅で進み、隣の要素を壊さずに保存する。
sizeofと配列配列全体のサイズと、ポインタのサイズを区別する。
空文字列・エスケープ空でも終端の１バイトを持ち、エスケープ後のバイト数を数える。
文字列中のコメント記号"/*"や"//"をコメントとして削除しない。
入力末尾のコメント終端を越えて読まず、閉じていなければエラーを示す。
