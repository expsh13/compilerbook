初期値は、いつ、どこで用意される？

プログラムの実行イメージと
初期化式

ファイルの中のバイト列が、実行中のメモリにつながる。
「最初から用意する値」と「動きながら求める値」を分けて考える。

この章の到達点int x = 13; が、書く場所によって「初期データ」または「値を書き込む処理」になる理由を説明できる。

原書「プログラムの実行イメージと初期化式」に対応。ここではLinux・x86-64、int＝４バイト、ポインタ＝８バイト。まず静的リンク・固定配置の単純な実行モデルで考える。動的リンクやPIEの詳細は次の学習範囲とする。

01ファイルから実行中のメモリへ

第３章では部品をリンクし、第６章ではメモリ上の変数を参照した。今回はその間、できあがった実行ファイルを、どう実行できる状態にするかをつなぐ。「実行イメージ」は画像ではなく、プログラムの命令やデータがメモリ上に配置された状態を指す。

まず比べたい２つの初期化
int base = 13;               // 関数の外：グローバル変数

int compute(int n) {
    int x = n + base;        // 関数の中：通常のローカル変数
    return x;
}

base の13は、プログラムの実行を始める前に用意できる。いっぽう x は、関数が呼ばれて引数 n が決まってから値を求める。同じ = を使う宣言でも、準備するタイミングが違う。

セクションとセグメントは、見る目的が違う

.text・.data・.bss などは、ファイル内の内容を分類するセクションの名前。OSがロードするときは、プログラムヘッダにあるセグメントの情報を見る。１つのロード用セグメントに複数のセクションが含まれることもある。

テキスト領域の「テキスト」は機械語を指し、ソースコードの文字列ではない。読み取り・書き込み・実行の権限も配置の情報に含まれる。

参照：ELFのプログラムヘッダ・AMD64 ABIのプロセス初期化。

02初期値をバイト列で用意する

まず、関数の外で定義した変数を考える。Cでは、このような変数は静的記憶域期間を持ち、プログラムの実行を通して存在する。初期値を準備するために、宣言の式をmainで毎回実行するわけではない。

この節の宣言は、すべて関数の外に置く
int base = 10 + 3;
int blank;
int values[4] = {6, 9};

10 + 3 は定数だけで求められるので、コンパイラは13を初期データにできる。blank は初期化式がなくても0になる。values の指定されていない要素も0で補う。

アセンブラへ渡す初期データの例（GNU as、x86-64）
.data
.balign 4
base:
    .long 13
values:
    .long 6, 9, 0, 0

.bss
.balign 4
blank:
    .zero 4

.bss は、ゼロで始まる領域をファイル内の実データとして並べずに表すためによく使う。.zero 4 をここに置くと、４バイトの領域が必要だと表せる。実行時のメモリではゼロが用意される。「ファイルにゼロの列がない」と「メモリを使わない」は違う。

同じ .zero でも、.data ならゼロのバイト列をファイルに出す。変数をどのセクションへ置くかは処理系の選択であり、Cの規則が要求するのは適切な初期値である。この環境では整数の0は全ビット0で表される。

参照：ELFのセクションとSHT_NOBITS・GNU asの.zero。

03アドレスの初期値を埋める

前章では、ポインタに「指す先の住所」を入れた。グローバル変数の初期値でも同じだ。ただし、コンパイル中には住所がまだ決まっていないことがある。そこで、名前とずれを残してリンカへ渡す。

配列の２番目を指すポインタを、最初から用意する
int values[4] = {6, 9};
int *second = values + 1;

values + 1 は１要素先、ここでは４バイト先。コンパイラは「valuesの住所＋４」と表せる。second 自身の８バイトに入るのは、9ではなく、その9がある場所のアドレスだ。

図の .quad values + 4 は、「valuesの住所に４バイト足した値を、８バイトで出す」というアセンブラへの指示。.long は４バイト、.quad は８バイトのデータを出す。未確定の住所は、オブジェクトファイルの再配置情報としてリンカへ伝える。

「住所を使う」と「変数の中身を読む」は違う

関数の外の初期化この章での扱い
int a = 10 + 3;定数式。初期データとして13を出せる。
int *p = &base;静的に存在する変数の住所。参照を残せる。
int b = base;不可。baseが13で始まっても、変数の値を読む式はこの定数式にならない。
int c = compute(5);不可。Cのグローバル変数の初期化に、関数の実行は使えない。

これは「OSにはmainより前に何も実行する能力がない」という意味ではない。Cの静的記憶域の初期化式に課される制約だ。C++の動的初期化や処理系の拡張機能とは分けて考える。

ポインタに足す定数も、指す配列の範囲や末尾の１つ先までという制約に従う。「名前＋定数なら任意の場所を参照できる」という意味ではない。

参照：C11委員会草案 §6.6・§6.7.9、GNU asの.quad。

04配列と文字列を初期化する

ここで追加するのは、宣言の時点で最初の値を与える書き方。初期化は、あとから変数へ代入する操作と、使える構文が同じとは限らない。配列の初期化がその例だ。

配列の要素を並べて初期化する
int a[4] = {6, 9};    // 6, 9, 0, 0
int b[] = {6, 9};     // 要素数は２と決まる
char word[] = "OK";   // 'O', 'K', '\0' の３要素

配列は、宣言後に a = {6, 9}; と書いてまとめて代入することはできない。コンパイラでも、宣言の = を読んだ後は、普通の代入式だけでなく、{ ... } や文字列による初期化を読み取る処理が必要になる。

文字列の住所を持つのか、文字の配列を作るのか

関数の外の宣言で比較する
char *message = "OK";
char word[] = "OK";

アセンブリでは .asciz "OK" と書くと、O・K・終端ゼロの３バイトを出せる。文字列のデータを並べる指示で、CPUの命令ではない。

コンパイラでは、どんな順に処理する？

宣言された型と初期化式を一緒に見る。数なら式を読み、配列なら要素ごとの初期化を並べる。長さが省略されていたら要素数から型を完成させ、多すぎる初期値はエラーにする。足りない要素はゼロとして記録する。その後、グローバルならデータ出力、通常のローカルなら書き込み処理へ変換する。

ここでは一次元配列を中心に扱う。構造体・多次元配列・指示付き初期化子など、Cの初期化構文全体の実装は別の段階とする。

参照：GNU Cの初期化式・C11委員会草案 §6.7.9。

05ローカル変数は実行中に初期化

次は、関数内の通常のローカル変数。初期化式は、実行がその宣言に到達するたびに評価される。引数を読んだり、関数を呼び出したりして初期値を求められる。

引数nが５なら20、８なら23を返す
int base = 13;

int compute(int n) {
    int x = n + base;
    int tmp[3] = {x, 2};
    return tmp[0] + tmp[1] + tmp[2];
}

n = 5 ならxは18、tmpは {18, 2, 0} になる。次に n = 8 で呼べば、今度のxは21、tmpは {21, 2, 0}。baseの13は呼び出すたびに初期化し直すものではない。

自作コンパイラが生成する処理の考え方
xの置き場に、n + base の結果を書く
tmp[0]の置き場に、xの値を書く
tmp[1]の置き場に、2を書く
tmp[2]の置き場に、0を書く
３要素を足し、返り値として返す

ここで配列の残りをゼロにするのも、初期化の一部。int tmp[3]; のように初期化式をまったく書かなかった自動変数の値は不定で、0とは限らない。値を入れる前に読んではいけない。

関数内にstaticと書いた変数は？

static int count = 13; は、関数内の名前でも静的記憶域期間を持つ。呼び出しを越えて同じ変数が残り、初期化は呼び出しのたびには行わない。Cでは初期化式にもグローバル変数と同じ種類の制約がある。「関数の中か外か」だけでなく、「通常の自動変数か、静的記憶域の変数か」を見分ける。

参照：GNU Cのローカル変数・静的ローカル変数。

06起動から初期化までを進める

同じファイルから実行を始め、前の節の compute(n) を１回呼ぶ。ファイルの初期データは変わらず、実行中のローカル変数だけが引数に応じて変わることを確かめよう。

0 / 10

nを変えると起動前へ戻る。１段階は説明のためのまとまりで、CPUの１命令ではない。メモリ配置・起動手順を簡略化したモデル。

開始前。まだファイルだけがあり、プロセスは作られていない。

実行ファイル：材料と命令

この観察では、初期化なしのグローバル変数 int blank; も一緒に配置する。

実行中のメモリ：いまの状態

実行位置
まだ実行していない

スタック・RSP
まだ用意されていない

返り値

関数を抜けると、xとtmpの寿命が終わる。メモリにビット列が残っていることと、変数として使い続けられることは違う。戻り先の保存・復元は第１章のcallとretの仕組みで行う。

07理解を確かめる

実行ファイルの先頭バイトから、そのまま命令を実行する？

そうとは限らない。ELFヘッダにある入口のアドレスと、プログラムヘッダの配置情報を使う。通常のCプログラムは起動用コードを経てmainへ進む。

グローバルのint base = 13; は、mainの先頭で13を代入する？

このモデルでは違う。初期データとして13のバイト列を用意し、実行前のメモリに反映する。mainがその宣言文を実行するわけではない。

.bssはファイルに中身がないなら、メモリも使わない？

実行時には領域が必要。ファイルにはゼロを並べず、大きさなどの情報で表している。

グローバルのint *p = &base; はよいのに、int x = base; はだめ？

住所への参照はシンボルとして残せる。一方、変数の中身を読む式は、Cの静的記憶域の初期化に使える定数式にならない。

ローカルのint a[4] = {6, 9}; の残りは不定？

初期化式があるので、残りの２要素は0になる。初期化式がまったくない自動変数と区別する。

char word[] = "OK"; のサイズは８バイト？

wordはポインタではなくchar配列。O・K・終端ゼロの３バイト。この環境で８バイトなのは文字列の住所を持つポインタの大きさ。

ローカル変数の初期化式で関数を呼べる？

通常の自動変数なら呼べる。宣言に到達したときに式を評価する。Cのstatic変数の初期化では同じようには扱えない。

実装したら、ここを確かめる

対象見たい結果
グローバルの定数・省略された初期値定数の値と、ゼロで始まる値をmainから読める。
配列へのポインタ初期化要素幅を掛けた位置を指し、意図した要素を読める。
配列長の省略・部分的な初期化長さが決まり、不足する要素が0になる。
通常のローカル変数呼ぶたびに、その時の引数や関数の返り値を使って初期化される。
不正な初期化グローバルでの関数呼び出しや、多すぎる配列要素を拒否する。
