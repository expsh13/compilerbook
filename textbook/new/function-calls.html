第８章

関数呼び出し

値を渡し、実行を移し、結果を受け取って続きを進める。

第６章で別の部品への接続を、第７章で値の保存場所を学びました。今回は両者をつなぎ、自作コンパイラが出す main から、別のファイルにある関数を呼び出せるようにします。

１この章で扱う問い

関数へ引数を渡し、元の計算を壊さずに結果を受け取るには、どんな命令が必要か？

f(3,5) を呼ぶとき、３と５はどこへ置くのでしょうか。また、1+f(3,g(4)) では、g を計算している間、外側の１と、先に用意した３をどこに残せばよいでしょうか。実行の移動だけでなく、値を守る仕組みまで追います。

前提は第５章の一時保存、第６章のリンク、第７章のスタックフレームです。本章では呼び出す側を自作し、呼ばれる関数の本体はＣで用意します。自作言語で関数本体を定義する構文や再帰の実装は、今回の範囲には含めません。

２この章の理論

まず、呼ぶ関数の働きを決める

functions.c に、次の３関数を用意しました。関数の括弧内に書く x や y は、渡された値に付ける名前で、仮引数と呼びます。呼び出す式に書く３や５は実引数です。

long f(long x, long y) {
    return x * 10 + y;
}

long g(long x) {
    return x * 2;
}

long h(void) {
    return 7;
}

f は第１引数を１０倍して第２引数を足します。f(3,5) は３５、f(5,3) は５３です。単なる和にしないことで、引数の順序を逆にした誤りを結果から見つけられます。g は２倍、h は引数なしで７を返します。

今回のリナックス x86-64 環境では long は８バイトです。第７章の変数や計算が使う６４ビットの値とそろえるため、これらの関数の引数と戻り値に long を使います。すべてのＯＳで long が８バイトとは限らないので、教材ファイルではそのサイズも検査します。

呼ぶ側と呼ばれる側が、同じ約束を使う

Ｃで書いた関数と、自作したアセンブリが値を受け渡せるのは、機械語レベルの約束を共有するからです。こうした約束を含む境界の仕様をＡＢＩと呼び、そのうち引数・戻り値・レジスタなどの受け渡し規則を呼び出し規約と呼びます。

本章の対象は、リナックスの x86-64 で使う System V AMD64 の規則です。今回のような整数の引数は、先頭から rdi、rsi、rdx、rcx、r8、r9 の順に渡し、整数の戻り値は rax で受け取ります。本章で実装する引数は最大２個なので、使うのは rdi と rsi までです。浮動小数点、構造体、可変個引数などは扱いません。

レジスタ自体を別々に所有して渡すわけではありません。実行を移す前後で、同じＣＰＵのレジスタを使います。図はその値をどちらの処理が用意し、どちらが利用するかを分けたものです。

call と ret は、実行する場所を変える

mov rdi, 3
mov rsi, 5
call f
add rax, 1

これは、引数が用意できていてスタックの条件も満たしている場合の、受け渡し部分だけの例です。最初の２行は値を置きます。call f は、次の add の位置を戻りアドレスとしてスタックに保存してから、f へ実行を移します。call 自体が３と５を計算したり、引数レジスタへ自動で並べたりするわけではありません。

f が rax に３５を用意し、ret で保存された場所へ戻ると、main は add rax, 1 を実行して３６にします。戻り値３５と、戻りアドレスは別の情報です。戻り値はデータで、戻りアドレスは続きの命令の場所です。

呼び出した後も、レジスタの値は残るのか

呼ばれた関数も計算のためにレジスタを使います。今回の規則では rax、rdi、rsi などの値は、呼び出し後も同じとは限りません。呼ぶ側が、後でも必要な値を保管しておく必要があります。これを呼び出し側で保存するレジスタと考えます。

反対に rbp や rbx などは、呼ばれる側が使い変えるなら、戻る前に元の値へ復元する約束です。第７章で main が入り口で rbp を保存し、終わりに戻していたのは、この約束に対応しています。rsp も、呼び出しから戻った時点で、呼ぶ直前の位置へ戻っている必要があります。

本章では、呼び出しをまたいで必要な途中結果をスタックに保存します。たとえば 1+g(4) の１は、g がレジスタを使っても失われません。g の戻り値８を受け取ってから１を取り出し、足し合わせます。

引数の中の関数呼び出しに備える

f(3,g(4)) では、第１引数３を rdi に置いたまま g を呼ぶ方法は危険です。g に渡す４も rdi に置く必要があり、さらに g 自身も rdi を変えてよいからです。

そこで、本章のコンパイラは引数を左から順に計算して一時保存し、すべてそろった後に引数レジスタへ置く方法を使います。２個の引数なら、第１引数を push、第２引数を push した後、逆順に pop して rsi、rdi に入れます。この左から右という評価順は教材の言語で決めたもので、Ｃの引数評価順の一般的な保証ではありません。

call の直前は、スタックの位置もそろえる

値を正しいレジスタへ置くだけでは不十分です。今回の整数だけの呼び出しでは、call を実行する直前の rsp を１６の倍数のアドレスにする約束があります。このように位置を一定の単位にそろえることをアラインメントと呼びます。

call は戻りアドレス８バイトを積むので、呼ばれた関数の入り口では、rsp を１６で割った余りは８になります。第７章の main はそこで rbp を push して８バイト進め、さらに２０８バイト（１６の倍数）を確保します。そのため、本文の開始時点の rsp は１６の倍数です。

本文で一時保存を１回すると、rsp はさらに８バイト動き、１６の倍数ではなくなります。２回なら合計１６バイトなので再びそろいます。コンパイラは、現在何個の一時保存値が積まれているかを depth という数で把握し、奇数個なら call の前に８バイト分の空きを足し、戻ったらその空きを戻します。

sub rsp, 8
call g
add rsp, 8

これは必要な場合だけ出す調整です。sub は空きを作るだけで、引数や戻り値を書き込む命令ではありません。add はその空きを使い終える操作で、rax の戻り値は変えません。引数用の一時保存を pop した後にも、外側の計算用の保存値が残っている可能性がある点が重要です。

呼び出し直前に残る保存値rsp の１６で割った余り追加する調整
０個、２個など偶数個０なし
１個、３個など奇数個８call 前に８を引き、戻ったら８を足す

単純な関数が偶然動いても、位置の規則を守れているとは限りません。呼び出し先がその前提で命令を使えば、違反した呼び出しが失敗する場合があります。教材には、この条件を直接検査する部品も用意しています。

構文木に、関数呼び出しを加える

今回の compiler.c は、第７章の文・変数・四則演算を残し、式の基本要素に呼び出しを加えています。

primary = 数 | 変数 | '(' expr ')'
        | 'f' '(' expr ',' expr ')'
        | 'g' '(' expr ')'
        | 'h' '(' ')'

名前の直後が開き括弧なら呼び出しとして読みます。呼び出しノードの op は 'c'、value は関数名の文字です。left は第１引数、right は第２引数の木を指します。引数がない位置は NULL にします。arity 関数は、f が２個、g が１個、h が０個という対応を返します。

この３関数の名前と個数は、今はコンパイラ内に固定しています。一般の関数宣言を読み取る仕組みはまだありません。f・g・h は関数用に予約するため、第７章と違って変数名には使えません。そのほかの変数は従来どおり小文字１文字です。

生成関数に、保存中の個数を渡す

生成関数は generate(node, depth) になります。depth は「この部分木の命令が動き始めるときに、外側が一時保存している８バイト値の個数」です。これはコンパイル中に数える情報で、生成プログラム内の変数ではありません。

二項演算の右の子を生成するときは、左の結果を１個 push 済みなので depth + 1 を渡します。呼び出しの第２引数を生成するときも、第１引数を保存済みなので同様です。生成された各部分木は、自分が追加した一時保存を片付け、結果を rax に残す約束を保ちます。

if (node->op == 'c') {
    int count = arity((char)node->value);
    if (count >= 1) {
        generate(node->left, depth);
        printf("    push rax\n");
    }
    if (count == 2) {
        generate(node->right, depth + 1);
        printf("    push rax\n");
        printf("    pop rsi\n");
    }
    if (count >= 1) printf("    pop rdi\n");
    if (depth % 2 != 0) printf("    sub rsp, 8\n");
    printf("    call %c\n", node->value);
    if (depth % 2 != 0) printf("    add rsp, 8\n");
    return;
}

第２引数を保存した直後に取り出すのは、すべての引数を保存してから逆順に配置する手順を、そのまま表しているためです。最短の命令列にする最適化は行いません。引数を取り出し終えると保存数は元の depth に戻るので、それを整列判定に使います。

出力された call f の参照先を、functions.o の f と結び付けるのは第６章のリンクの仕事です。リンカーが引数を並べ直すわけではありません。呼ぶ側が正しい引数を用意し、リンクで接続先が決まり、実行時に初めて値が渡ります。

本章は整数の固定個引数、最大２個の呼び出しに限定します。printf のような可変個引数の関数は、別の規則も必要なのでこの仕組みのまま呼びません。ゼロ除算・整数の範囲超過は引き続き扱わず、最終結果の観察には０〜２５５の終了状態を使います。

３ハンズオン

準備：呼ぶ側の生成器と、呼ばれる部品を作る

第１章と同じリナックスのコンテナ内で実行します。まだ入っていなければ、マック側のリポジトリで make -f docker.mk shell を実行してください。

cd /workspace/textbook/new/labs/ch08
gcc -std=c11 -Wall -Wextra -o /tmp/ch08-compiler compiler.c
gcc -std=c11 -Wall -Wextra -O0 -c functions.c -o /tmp/ch08-functions.o

２行目は自作コンパイラ自身の実行ファイルを作ります。３行目はＣの関数の本体をオブジェクトにします。-c なので、まだリンクはしません。-O0 は最適化を抑える指定です。どちらも成功したことを確認して次へ進みます。

実験１：引数の順序を確認する

実行前に：f(3,5) の結果と、３と５が入るレジスタを予想します。

/tmp/ch08-compiler 'f(3,5);' > /tmp/ch08-result.s
cat /tmp/ch08-result.s
gcc /tmp/ch08-result.s /tmp/ch08-functions.o -o /tmp/ch08-program
/tmp/ch08-program
echo $?

１行目は命令の生成、２行目はその表示、３行目はアセンブル・リンクです。４行目で初めて生成プログラムが動きます。echo $? はその終了状態の表示です。入力全体を引用符で囲み、括弧やセミコロンをシェルではなくコンパイラへ渡しています。

実行後に開く：逆順に取り出し、正しい順序へ配置する

結果は３５です。３、５の順に push した後、最後の５を rsi、残る３を rdi へ pop します。表示されたコードで、この順序と call f を確認してください。

同じ手順で入力を f(5,3); に変えます。生成とリンクをやり直してから実行してください。

結果を照合する

５３です。引数の順序も関数への入力の一部なので、同じ二つの数でも結果が変わります。

実験２：関数呼び出しを、引数の中へ入れる

f(3,g(4)); を実験１と同じ手順で生成・リンク・実行します。実行前に、g に渡す値、g から戻る値、最後に f に渡す二つの値を書いてください。

実行後に開く：先に g、後で f

g は４を受け取って８を返します。その後に f へ３と８を渡すので結果は３８です。生成された命令では call g が call f より前に現れます。先に求めた３は、g を呼んでいる間スタックで待ちます。

続けて f(g(3),h()); を試してください。今度は第１引数も第２引数も関数呼び出しです。

結果を照合する

g(3) の６と h() の７を f に渡すので、６７になります。h には引数を渡しませんが、実行の移動・戻り値の受け取り・スタック位置の調整は必要です。

実験３：外側の途中結果と、ローカル変数を守る

次の二つの入力を、一つずつ実験１と同じ手順で試します。どの値をスタックに残して呼び出しているか考えます。

1+f(2,g(3));
a=9; g(3); a;
実行後に開く：計算用の保存と、変数用の保存

最初は g(3) が６、f(2,6) が２６で、最後に待っていた１を足して２７です。次は９です。g が返した６は途中の文の値にすぎず、最後の文で a の９を読み直します。g に a の保存先を渡していないので、g は今回の a を書き換えません。

最初の入力で call f の直前を見ると、外側の１がまだ保存中なので、sub rsp, 8 が出ます。一方、g を呼ぶ直前は外側の１と f の第１引数２が保存中で、２個なので追加の８バイトは不要です。調整は、呼ぶ関数名ではなく、その時点の保存数で決まります。

実験４：規則を守れているか、厳しい部品で確かめる

単純なＣの関数だけでは、たまたまレジスタの値が残り、誤りを見逃すことがあります。検証用の probe.s は同じ f・g・h を定義しますが、入り口でスタック位置を検査し、戻る前に変更してよい作業用レジスタを意図的に書き換えます。rax の戻り値と、保存すべきレジスタは守ります。

gcc -c probe.s -o /tmp/ch08-probe.o
/tmp/ch08-compiler '1+f(2,g(3));' > /tmp/ch08-result.s
gcc /tmp/ch08-result.s /tmp/ch08-probe.o -o /tmp/ch08-probe-program
/tmp/ch08-probe-program
echo $?

今回は functions.o の代わりに probe.o をリンクします。両方とも同じ名前を定義するため、両方を一緒に渡してはいけません。スタック位置が違えば、検証用部品は意図的に不正命令で停止します。これはエラーを確実に検出するための仕組みで、本番の関数が必ず同じように止まるという意味ではありません。

実行後に開く：通常版と同じ２７になる

正しく保存と整列ができていれば、作業用レジスタを上書きされても２７です。probe.s の検査は、関数の入り口で rsp を１６で割った余りが８かを調べています。call 直前の条件は０であり、call が戻りアドレスを積むため入り口では８になる、という違いに注意してください。

実験５：解析の失敗と、リンクの失敗を分ける

/tmp/ch08-compiler 'f(3);' > /tmp/ch08-rejected.s
echo $?

f は引数２個と決めているため、この入力はコンパイラが拒否します。終了状態は１、アセンブリの出力は空です。> 自体は先に処理されるので空のファイルは作られますが、そのビルドには進みません。

一方、正しい呼び出しを生成しても、本体の部品を渡し忘れると、失敗する段階が変わります。

/tmp/ch08-compiler 'f(3,5);' > /tmp/ch08-result.s
echo $?
gcc /tmp/ch08-result.s -o /tmp/ch08-missing
echo $?
実行後に開く：命令を作れることと、本体がそろうことは別

コンパイラは成功して０を返しますが、リンクは f の定義を見つけられず失敗します。今回のコンパイラは f の名前と個数を知っていても、その本体を自動でリンクする道具ではありません。第６章で見た、参照を満たす部品が不足した状態です。

まとめて確認するには、第８章のフォルダで bash check.sh を実行します。検証スクリプトは通常のＣの部品と検査用の部品の両方で、引数の順序、入れ子、変数、負の途中結果などを確認します。教材の compiler.c を変更した場合は、元の内容へ戻してから使ってください。

４理解チェック

call f が実行されると、引数が自動で rdi と rsi に入るか？

解説を読む

入りません。呼ぶ側が事前に配置します。call は戻りアドレスを保存して実行を移す命令です。引数の意味は、両者が従う呼び出し規約によって決まります。

戻り値と戻りアドレスは、どこにあるか？

解説を読む

今回の整数の戻り値は rax、戻りアドレスは call がスタックへ保存した続きの位置です。ret は戻りアドレスを使います。計算結果を rax へ入れる仕事は、呼ばれた関数が先に行います。

f(3,g(4)) で、３をすぐ rdi に置いて待ってはいけないのはなぜか？

解説を読む

g に渡す４も rdi を使い、さらに g 自身がそのレジスタを変更してよいからです。３をスタックに保存し、g の結果を求め終えてから、f の引数レジスタへ配置します。

引数をすべて pop したなら、整列のための調整は不要か？

解説を読む

必ずしも不要ではありません。外側の式が保存した値が残る場合があります。1+h() なら h に引数はありませんが、外側の１が１個保存中なので、追加の８バイトが必要です。

なぜ呼び出した関数の rbp が、main の変数を壊さないのか？

解説を読む

呼ばれた関数が rbp を使い変えるなら、元の値を保存し、戻る前に復元する約束だからです。main の変数は main が確保した領域に残ります。呼び出し先の一時領域は、それより小さいアドレス側に作られます。呼び出し先が必ず rbp を使うとは限りません。

自作言語の入力に f の定義がなくても、呼べるのはなぜか？

解説を読む

呼び出し側は参照を含む命令を生成し、Ｃで作った別のオブジェクトが定義を提供するからです。リンクが名前を結び付け、呼び出し規約が値の受け渡しをそろえます。どちらか一方だけでは正しい関数呼び出しになりません。

参照先

System V AMD64 ＡＢＩの公式資料の関数呼び出し規則と、原書「低レイヤを知りたい人のためのＣコンパイラ作成入門」の関数呼び出しに対応します。本章は３種類の外部関数に範囲を絞り、引数の一時保存とスタック位置の調整を明示しています。

教材のリナックス環境で、通常のＣの部品と、整列・レジスタの保存を調べる検証用部品の両方を使って動作を確認します。

第７章　ローカル変数とスタック第９章　整数の表現
