第３章

字句解析

文字を一つずつ読み、次の処理が使える「数」と「記号」にまとめる。

前章のコンパイラは、入力全体を整数１個として読みました。今回は 12 + 3 を、数１２、記号＋、数３として取り出します。式の意味を考える前に、その材料をそろえる段階です。

１この章で扱う問い

ソースコードの文字列から、意味のある単位をどう取り出すか？

12 は２文字ですが一つの数です。一方、1 2 は空白で分かれた二つの数です。この違いを保ちながら、数や記号を左から順に読み取る仕組みを作ります。

第２章の文字列、繰り返し、数字から数値への変換を使います。本章では字句解析器を単独で動かし、出力を観察します。前章のコンパイラは残します。命令の生成への接続は、式の構造を扱う次章以降で進めます。

２この章の理論

文字列を、トークンの並びにする

トークンとは、数や記号など、後続の処理が一まとまりとして扱う単位です。文字列を読んでトークンの並びを作る処理を字句解析、それを行う部分を字句解析器と呼びます。

トークンに何を保存するか

次の処理では「これは数か、記号か」を知る必要があります。また、数なら値が必要です。エラーが起きた場所を説明できるよう、入力のどの範囲から取り出したかも保持します。今回の実装では、これらを一つにまとめた Token という構造体を使います。

typedef enum { NUMBER, SYMBOL, END } TokenKind;

typedef struct {
    TokenKind kind;
    size_t start;
    size_t length;
    int value;
} Token;

enum は種類に名前を付ける仕組みで、NUMBER は数、SYMBOL は記号、END は終了を表します。struct は複数の項目をまとめます。typedef によって、その型を Token と短く書けます。

入力が「12 + 3」のときの保存内容
種類開始位置長さ数値
数１２０２１２
記号＋３１使わない
数３５１３
終了６０使わない

start と length は、元の文字列の開始位置と長さです。位置は０から数え、size_t はサイズや添字を表す整数型です。今回の入力は半角文字なので、文字の位置とバイト位置が一致します。日本語などの多バイト文字の位置表示は扱いません。

記号の種類は source[token.start] で元の文字列から読めます。つまり SYMBOL だけで＋と－を区別しているわけではありません。元の文字列を参照する設計なので、トークンを使い終わるまで入力文字列も保持します。value は数トークンにだけ使い、他の種類では０を入れておきます。

読み取り位置は「次に読む文字」を指す

入力を左から読むため、pos という位置を持ちます。その位置の文字に応じて、空白なら一文字進む、数字なら数字が続く限り読む、記号なら一文字のトークンにする、という処理を繰り返します。

空白は先に全部削除しません。1 2 の空白を削ると 12 になり、別の数へ変わってしまうからです。数を読む処理を空白で止め、次の繰り返しでその空白を飛ばすことで、境界を残します。

どの文字を受け付けるか

今回扱うのは、０〜２５５の整数、記号 + - * / ( )、空白・タブ・改行です。数の範囲は前章にそろえた教材上の制限です。記号はすべて一文字で、== のような複数文字の記号はまだ扱いません。

字句解析の成功は、式としての正しさを保証しません。9 + も、1 2 も、ここではトークンに分けられます。数や記号の並びが正しいか、括弧が対応するか、掛け算を先に行うかは、次章の構文解析が扱う問題です。

空の入力にも終了トークンを一つ付けます。END は元のソースに書かれた記号ではなく、後続の処理が「もう材料がない」と判断するために字句解析器が追加する印です。Ｃの文字列の終端 '\0' は入力の終わり、終了トークンは出力の終わりを表します。

実装の中心を読む

全体は tokenize.c にあります。tokenize は入力 source を読み、配列 tokens に順番にトークンを保存します。count は保存した個数です。成功なら true、失敗なら false を返します。

while (source[pos] != '\0') {
    if (isspace((unsigned char)source[pos])) {
        pos++;
        continue;
    }
    size_t start = pos;
    /* この後で、数字・記号・不明な文字に分けて処理する。 */
}

これは外側の繰り返しの抜粋です。isspace は空白類かを判定する関数です。文字を安全に渡すため unsigned char に変換しています。pos++ は次の文字へ進む操作、continue は今回の繰り返しの残りを飛ばして次へ進む操作です。空白以外なら、読む前の位置を start に保存します。

int value = 0;
while (source[pos] >= '0' && source[pos] <= '9') {
    value = value * 10 + (source[pos] - '0');
    if (value > 255) {
        fprintf(stderr, "位置%zu：整数は０〜２５５で入力してください。\n", start);
        return false;
    }
    pos++;
}
tokens[(*count)++] = (Token){NUMBER, start, pos - start, value};

この部分は、最初の文字が数字だと確認した後に入ります。&& は両方の条件を満たすという意味です。前章と同じ方法で数値を組み立て、数字以外に出会ったら止めます。最後の pos - start が読んだ文字数になります。

(Token){...} は、構造体の項目順に「種類・位置・長さ・数値」を入れた一つのトークンです。*count は呼び出し元の個数を参照し、(*count)++ は現在の個数を配列の添字に使ってから一つ増やします。配列の次の空き場所へ追加する書き方です。

記号の場合は strchr("+-*/()", source[pos]) で対応する文字が一覧に含まれるかを調べます。見つかれば長さ１のトークンを追加し、一文字進みます。数字でも記号でも空白でもなければ、位置付きのエラーを標準エラー出力に書きます。

呼び出し側の main は calloc で配列用のメモリを確保し、字句解析に成功したら各トークンを printf で表示します。最大でも一文字につき一トークンなので、入力の長さ＋１個分を確保すれば終了トークンも収まります。最後に free で確保したメモリを解放します。

表示はトークンを観察するためのものです。次の構文解析へ渡す本体は配列です。また、途中でエラーになった場合は配列を表示せず終了するので、成功した一部分だけを完成した出力と誤解せずに済みます。

３ハンズオン

準備：字句解析器を実行ファイルにする

前章と同じコンテナを使います。閉じていたら、マック側のリポジトリで make -f docker.mk shell を実行して入り直します。以下はコンテナ内で実行します。

cd /workspace/textbook/new/labs/ch03
gcc -std=c11 -Wall -Wextra -o /tmp/ch03-tokenize tokenize.c

cd は実験ファイルのあるフォルダへ移動します。gcc はＣで書いた字句解析器をコンパイル・リンクし、/tmp/ch03-tokenize という実行ファイルを作ります。ここでは、入力式の実行ファイルを作っているわけではありません。

実験１：複数桁の数と位置を見る

入力 12 + 3 のトークン数、数の値、開始位置、長さを予想してから実行します。終了トークンも数えてください。

/tmp/ch03-tokenize '12 + 3'
echo $?

引用符によって、空白や記号を含む文字列全体を一つの引数として渡します。引用符自体は入力に含まれません。echo $? は、直前の字句解析器が成功したかを表示します。式の計算結果を表示するものではありません。

実行後に開く：出力の読み方
数 値=12 位置=0 長さ=2
記号 '+' 位置=3 長さ=1
数 値=3 位置=5 長さ=1
終了 位置=6 長さ=0

最後の echo は０を表示します。１２を一つの数として取り出し、空白はトークンにせず、元の文字列での位置は保っています。

実験２：空白が変えるもの、変えないもの

/tmp/ch03-tokenize '12+3'
/tmp/ch03-tokenize '12 + 3'
/tmp/ch03-tokenize '1 2+3'

各入力について、種類・値の並びと、位置・長さを分けて比較します。最初の二つは何が一致するでしょうか。三つ目では数トークンがいくつになるでしょうか。

比較後に開く

最初の二つは数１２、＋、数３、終了という並びが同じですが、位置が異なります。三つ目は数１、数２、＋、数３、終了です。空白は数字の連続を終わらせるため、１と２をまとめません。

実験３：字句解析の成功と、式の正しさを分ける

/tmp/ch03-tokenize '9 +'
echo $?
/tmp/ch03-tokenize '9 @ 3'
echo $?

それぞれ成功するか、エラーになるなら何文字目かを先に考えます。成功・失敗だけでなく、どの処理に責任があるかも説明してみてください。

実行後に開く

9 + は数・＋・終了になり、終了状態は０です。右側の数がないことは構文解析で検出します。9 @ 3 は位置２の @ を扱えないため失敗し、終了状態は１です。標準出力へは何も表示せず、エラーを標準エラー出力へ出します。

実験４：扱える記号を一つ増やす

マック側の別ターミナルで、次のファイルを編集します。コンテナと同じファイルを共有しています。

nvim /Users/hatasatoki/Develops/compilerbook/textbook/new/labs/ch03/tokenize.c

strchr("+-*/()", source[pos]) の一覧へ % を追加し、strchr("+-*/()%", source[pos]) にします。ここで増やすのは文字の認識だけです。変更後、コンテナ内で再ビルドして実行します。

gcc -std=c11 -Wall -Wextra -o /tmp/ch03-tokenize tokenize.c
/tmp/ch03-tokenize '9 % 4'

どのような出力になるか予想してください。この変更だけで、余りの計算までできるようになったでしょうか。

変更後に開く

数９、記号％、数４、終了が表示されます。％を記号として認識できるようになっただけで、計算はしていません。余りを求める意味の扱いと命令生成は、別途必要です。確認後は記号の一覧を元に戻し、再ビルドしてください。

この章の区切りは、読み取り位置の変化からトークン列を予想でき、文字として認識できることと式として正しいことを分けて説明できたときです。

４理解チェック

007-2 の最初のトークンの値と長さは？

解説を読む

値は７、長さは３です。数値としての意味と、元のソースで占める範囲は別に保持します。次の－の開始位置は３です。

-12 は、一つの負の数トークンになるか？

解説を読む

今回の規則では、記号－、数１２、終了の三つです。－が数を負にする操作か、二つの式の引き算かは、並びを読む次の段階で判断します。

数字の読み取りを while から一回だけの処理へ変えたら？

解説を読む

１２を読んでも、一文字目の１だけでトークンを作ってしまいます。次の繰り返しで２を別のトークンにするため、複数桁の数をまとめられなくなります。

空の入力と、空白２文字の入力はどう違う？

解説を読む

どちらも終了トークンだけになりますが、その位置はそれぞれ０と２です。字句解析は成功します。式として材料が足りるかどうかは、構文解析で確かめます。

入力 2+3*4 を字句解析すれば、優先順位は決まるか？

解説を読む

決まりません。ここで得るのは数２、＋、数３、＊、数４、終了という並びです。この並びから「３と４の積を２に足す」という構造を作るのが、次章の構文解析です。
