第７章

ローカル変数とスタック

名前を保存場所に対応させ、後の計算でその値を使う。

第５章のコンパイラへ戻り、変数と複数の文を追加します。計算した値を一度使って終えるだけでなく、名前を付けて保存し、後から読み出したり書き換えたりできるようにします。

１この章で扱う問い

ソースに書いた変数名は、実行中のどこに対応し、代入や読み出しはどんな命令になるか？

今回の入力は a=3; b=5; a+b*2; です。３を a に保存し、５を b に保存し、最後に保存した値を使って１３を求めます。計算中に rax を上書きしても a と b の値が残るよう、レジスタとは別の保存場所を用意します。

前提は第４章の構文木と、第５章の「式の結果は rax」「途中の左の値は push で保存する」という約束です。今回は、その一時保存とは用途の異なる領域を、同じスタック上に用意します。

２この章の理論

今回の小さな言語を決める

a=3;
b=5;
a+b*2;

セミコロン ; で終わる一つの処理を、ここでは文と呼びます。上から順に文を実行し、最後の文の値を、生成する main の返り値にします。代入文の値は、代入した値です。この「最後の文の値を返す」という規則は教材独自のもので、Ｃの main が自動的に同じ動作をするわけではありません。

変数名は a から z の小文字１文字、値は８バイトの整数として扱います。宣言を書く構文はまだ用意せず、最初の代入から利用できることにします。数の入力は第５章と同じ０〜２５５ですが、計算や変数の値までこの範囲に制限しているわけではありません。四則演算と括弧を使えます。

代入は文としてだけ扱います。a=a+1; は使えますが、a=b=3; や (a=3)+2; は扱いません。分岐、ループ、複数の関数、型の宣言、単独の負号もまだありません。扱う範囲を絞り、変数の保存と読み出しに集中します。

変数名は、保存場所を決めるための手がかり

ＣＰＵの計算命令が a という文字を検索するわけではありません。コンパイラが「a の値はこの場所、b の値はその隣」と先に決め、その場所を読む命令や書く命令を出します。

本章では a に８バイト、b に次の８バイト、というように、２６個の場所を固定で割り当てます。使っていない名前の分も確保する単純な実装です。実際に使った変数だけへ場所を割り当てる方法は、名前の管理を拡張するときに考えられます。

動く rsp と、基準として保つ rbp

第５章では、push と pop のたびに、スタックの先頭を指す rsp が変わりました。この動く位置だけを基準にすると、同じ変数を読むための距離も、計算の途中で変わってしまいます。

そこで、本章では rbp という別のレジスタを、関数内の固定した基準として使います。関数の入り口で基準を決め、本文の計算中には変えません。a は rbp - 8、b は rbp - 16、z は rbp - 208 という位置にします。基準からの距離をオフセットと呼びます。

これは今回選んだ実装方法です。変数が必ずスタック上に置かれる、あるいは全コンパイラが必ず rbp を使う、という意味ではありません。最適化したコードでは、値をレジスタに置いたり、変数の保存自体を省いたりすることもあります。

関数の入り口で、保存領域を確保する

push rbp
mov rbp, rsp
sub rsp, 208

最初の push rbp は、呼び出した側が使っていた rbp の値を保存します。自分の基準として rbp を使い直す前に、元へ戻すための値を残しておくわけです。次の mov rbp, rsp で、その保存位置を今回の関数の基準にします。

sub rsp, 208 は、rsp を小さいアドレスの方向へ２０８バイト移します。２６個×８バイトの変数領域を、自分が使う範囲として確保する操作です。ＯＳへメモリ確保を依頼する命令ではなく、スタックの使用位置を動かしています。また、領域内の値を０にする処理でもありません。

こうした関数の入り口の準備をプロローグ、一回の関数実行のために用意するスタック上の領域をスタックフレームと呼びます。今回の生成プログラムで変数を持つ関数は main 一つです。

角括弧は、そのアドレスにあるメモリを表す

mov rax, 3
mov [rbp - 8], rax
mov rax, [rbp - 8]

１行目はレジスタに３を入れます。２行目は、rbp から８バイト手前のメモリへ rax の値を保存します。これが a への代入です。３行目は、同じ場所のメモリから値を読み、rax に入れます。これが式の中で a を使う操作です。

角括弧の内側は場所を計算する式で、その場所にある値を読み書きします。rbp - 8 と書いても rbp 自体は変わりません。また、この命令の８は「変数の値から８を引く」指定でもありません。rax と組み合わせているので、この例では８バイトを読み書きします。

a=a+1; では、まず a の現在の値を読み、１を足し、その結果を同じ a の場所へ書き戻します。一度代入した値を変えられるのは、後の命令でその場所を上書きできるからです。

文法と構文木を、必要な分だけ広げる

program = statement+
statement = 名前 '=' expr ';' | expr ';'
expr = mul (('+' | '-') mul)*
mul = primary (('*' | '/') primary)*
primary = 数 | 名前 | '(' expr ')'

末尾の + は１回以上の繰り返しです。プログラムは文の列になり、各文は代入か、式だけの文です。四則演算の優先順位は変えず、式の基本要素に変数名を加えます。引用符内の記号は入力に書く記号で、引用符そのものは入力しません。

今回の compiler.c は第５章を土台にしています。字句解析は名前を IDENT という種類のトークンにし、= と ; も読み取ります。構文解析の statement は、先頭が「名前、その次が＝」なら代入文、それ以外なら式の文として読みます。

構文木には、変数の読み出しを表す 'v' と、代入を表す '=' のノードを追加します。既存の value フィールドは、数のノードでは数値、変数と代入のノードでは保存位置までの距離として使います。たとえば a のノードでは８です。ノードの種類により、同じフィールドでも意味が違います。

名前から距離を求める式は (名前 - 'a' + 1) * 8 です。a なら８、b なら１６になります。これはコンパイル中の対応付けです。実行時には、具体的な rbp の値と組み合わせて実際のメモリ位置が決まります。

読み出しと代入のコードを生成する

if (node->op == 'v') {
    printf("    mov rax, [rbp - %d]\n", node->value);
    return;
}
if (node->op == '=') {
    generate(node->right);
    printf("    mov [rbp - %d], rax\n", node->value);
    return;
}

読み出しノードでは、その場所の値を rax に入れる命令を出します。これで第５章の「部分木の結果は rax」という約束を守れます。代入ノードでは、右辺の命令を先に出し、その結果の rax を保存する命令を出します。保存しても rax は変わらないため、代入文の値も rax に残ります。

プログラム全体では、各文の木の根を配列に保存し、順番に generate を呼びます。一つの文を出力するたびに ret を出すのではありません。すべての文の命令を並べ、最後に一度だけ戻ります。四則演算の生成は第５章のままなので、一時保存の push と pop も引き続き対応します。

読み出す前に、値を入れたか確かめる

領域を確保しただけでは、そこに３や０が入っているとは限りません。そのため本章のコンパイラは、assigned[26] という配列で、各変数へすでに代入したかを確認します。最初はすべて偽で、右辺を解析して文末まで確認できた後に、その変数を代入済みにします。

最初の文が a=a+1; なら、右辺の a を読む時点では代入前なので拒否します。a=3; a=a+1; なら、２文目で読む a は代入済みなので受け付けます。この配列が持つのはコンパイル中の「代入したか」という情報で、実行中の a の値ではありません。

今回は文が上から順に必ず実行されるため、この単純な検査で足ります。分岐やループを加えた言語では、どの経路でも代入済みかなど、別の考慮が必要です。入力全体の検査に成功してから出力を始めるので、後半の文が不正なら途中までのアセンブリも出力しません。

関数から戻る前に、スタックを元へ戻す

mov rsp, rbp
pop rbp
ret

mov rsp, rbp で、変数用の領域を使い終え、保存しておいた呼び出し側の rbp の位置まで rsp を戻します。pop rbp がその値を復元すると、rsp は戻りアドレスを指します。最後の ret で、呼び出し側の続きへ戻れます。この終わりの処理をエピローグと呼びます。

この３命令は rax を書き換えないので、最後の文の値が返り値として残ります。「領域を使い終える」は、メモリの内容を０に消すことではありません。その領域は後の処理で再利用され、今回の関数の変数としては使えなくなります。

ここで実装するのは、生成した main の実行中に使うローカル変数です。外部へ公開するシンボル a を作るわけではないため、第６章のリンカーが a の場所を探すことはありません。Ｃと同じ型やスコープの規則をすべて備えた実装でもありません。

３ハンズオン

準備：変数を扱うコンパイラを作る

第１章と同じリナックスのコンテナ内で実行します。まだ入っていなければ、マック側のリポジトリで make -f docker.mk shell を実行します。その後、コンテナ内で次を実行してください。

cd /workspace/textbook/new/labs/ch07
gcc -std=c11 -Wall -Wextra -o /tmp/ch07-compiler compiler.c

１行目は実験用フォルダへの移動、２行目はコンパイラ自身のビルドです。-std=c11 はＣの規格、-Wall -Wextra は警告、-o は出力先の指定です。エラーなく完了してから次へ進みます。以前の章のファイルは変更しません。

実験１：名前が保存命令になるところを見る

実行前に：a=3; b=5; a+b*2; の最後の値を予想し、a と b が何バイト手前の場所を使うかメモしてください。

/tmp/ch07-compiler 'a=3; b=5; a+b*2;' > /tmp/ch07-result.s
echo $?
cat /tmp/ch07-result.s

引用符で文の列を一つの引数にしています。付けないと、セミコロンをシェルがコマンドの区切りとして扱ってしまいます。> はコンパイラの標準出力をファイルへ保存し、cat はその内容を表示します。ここでの終了状態０はコンパイラの成功で、式の計算結果ではありません。

表示の中から、a に書く命令 mov [rbp - 8], rax と、後から読む命令 mov rax, [rbp - 8] を探します。b に対応する１６も見つけてください。続いて生成されたプログラムを動かします。

gcc -o /tmp/ch07-program /tmp/ch07-result.s
/tmp/ch07-program
echo $?

１行目はアセンブル・リンク、２行目は生成プログラムの実行、３行目はその終了状態の表示です。ビルドに失敗した場合は先へ進まず、エラーを確認します。

実行後に開く：結果と保存場所

１３が表示されます。a と b は別の場所に保存され、最後の計算ではそこから３と５を読みます。途中で rax の内容が変わっても、メモリの a と b は、書き込み命令が出ない限りそのままです。

実験２：値のコピーと、名前のつながりを区別する

次は a=3; b=a; a=9; b; です。最後の b は３でしょうか、９でしょうか。b=a が、何を読み、どこへ書く命令になるかを根拠に考えます。

/tmp/ch07-compiler 'a=3; b=a; a=9; b;' > /tmp/ch07-result.s
cat /tmp/ch07-result.s
gcc -o /tmp/ch07-program /tmp/ch07-result.s
/tmp/ch07-program
echo $?
実行後に開く：コピーしたのは、その時点の値

結果は３です。b=a は a の場所から現在の３を読み、b の場所へ保存します。b が永久に a を参照する仕組みではありません。後の a=9 は a の場所だけを上書きするため、b に保存した３は残ります。

同じ手順で a=3; a=a+4; a; も試します。入力を変えるたびに生成・アセンブルとリンク・実行を行ってください。古い実行ファイルを動かしても、新しい入力の結果にはなりません。

再代入の結果を照合する

７です。右辺で古い３を読み、４を足した結果を、同じ a の場所へ書き戻しています。

実験３：変数の値と、一時保存の値を追う

a=3; b=5; (a+b)*(a+2); を実験２と同じ手順で生成してください。実行前に、生成された push rax が何を保存しているかを追い、式の計算中に a へ書き込む命令があるか確認します。

特に、左の a+b の結果を保存した後、右の a+2 を求めるときの状態を考えます。rsp は動きますが、a の位置を表す式は変わるでしょうか。予想ができたらビルド・実行します。

実行後に開く：８を待たせたまま、a から３を読める

結果は４０です。左側の８を一時保存している間も、a は rbp−8 の場所に３を保持しています。右側はそこから３を読み、２を足して５になります。最後に保存した８と掛けます。式の中で行う push は変数領域より外側なので、a の３を上書きしません。

実験４：代入前の読み出しを拒否する

/tmp/ch07-compiler 'a=a+1;' > /tmp/ch07-rejected.s
echo $?
cat /tmp/ch07-rejected.s

今回は意図した失敗です。エラーは標準エラー出力へ出るので画面に見えます。標準出力のファイルは作られますが、アセンブリは出力されません。拒否されたファイルのビルドへは進みません。

実行後に開く：保存領域があることと、値が決まっていることは別

右辺の a がまだ代入前なので、終了状態は１です。領域を確保する命令があっても初期値が決まるわけではありません。一方、a=0; a=a+1; a; は有効で、生成されたプログラムは１を返します。同じ１でも、前者はコンパイラのエラー、後者は生成プログラムの値です。

実験５：異なる変数が、同じ場所を使ったら？

これは、場所の対応を意図的に壊す実験です。コンパイラのソースは変えず、まず正常な a=3; b=5; a+b*2; のアセンブリを生成します。

/tmp/ch07-compiler 'a=3; b=5; a+b*2;' > alias.s

今回は、マック側のエディタでも編集できるよう、共有しているリポジトリ内に生成します。マック側で textbook/new/labs/ch07/alias.s を開き、[rbp - 16] を２か所とも [rbp - 8] に変更して保存してください。これは実験で作るファイルで、教材の compiler.c とは別です。変更後、a と b がどの値を読むか予想してから、コンテナ内で次を実行します。

gcc -o /tmp/ch07-alias alias.s
/tmp/ch07-alias
echo $?
実行後に開く：名前が違っても、命令が同じ場所を指せば上書きされる

結果は１５です。b=5 のつもりの命令が a の場所を５で上書きし、最後の a と b の読み出しも、ともにそこから５を読みます。ＣＰＵは元の変数名を区別して守ってくれるわけではありません。別々の変数を別々の場所へ対応付けることが、生成側の責任です。

確認用の 検証スクリプトは、コンテナ内の第７章フォルダで bash check.sh と実行できます。compiler.c から一時フォルダに生成して検証するので、実験５の alias.s は使いません。

４理解チェック

sub rsp, 208 を実行すれば、a は０になるか？

解説を読む

なりません。保存領域を使うために rsp を移しただけで、値を書き込んでいません。今回のコンパイラが代入前の読み出しを拒否するのは、この未確定の値に依存した実験にしないためです。

push rax の後でも、同じ rbp−8 で a を読めるのはなぜか？

解説を読む

push が変えるのは rsp であり、本文の rbp は固定しているからです。a は先に確保した変数領域にあり、一時保存はそれより小さいアドレス側を使います。

mov rax, [rbp - 8] は、rbp から８を引いた値を rax に入れる命令か？

解説を読む

いいえ。rbp−8 をアドレスとして、その場所のメモリに入っている値を読みます。角括弧がメモリを読むことを示しています。rbp 自体も変わりません。

なぜ ret の前に、rsp と rbp を戻すのか？

解説を読む

rsp が変数領域を指したままだと、ret が正しい戻りアドレスを取り出せません。また、呼び出し側の rbp を壊さないよう元の値も復元します。結果の rax はそのまま残し、使った保存領域と基準だけを片付けます。

コンパイラ内の assigned 配列に、a の値３が入るのか？

解説を読む

入りません。この配列には、代入済みかどうかだけが入ります。実行中の３は、生成された保存命令によって、そのプログラムのスタックに書き込まれます。コンパイラの実行時と、生成プログラムの実行時を区別します。

今回の８バイトの変数は、Ｃの int と同じ仕様か？

解説を読む

違います。本章の変数は教材独自の８バイトの保存場所です。生成する main の返り値は既存環境の int の規則に従い、シェルではさらに下位８ビットの終了状態を観察します。大きい値をそのまま画面に表示する仕組みではありません。ゼロ除算や６４ビットを超える計算への対応も、第５章から追加していません。

第６章　分割コンパイルとリンク第８章　関数呼び出し
