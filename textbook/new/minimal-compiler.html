第２章

最小のコンパイラ

前章で手書きした命令を、今度はプログラムに作らせる。

前章では、アセンブリを書いて実行ファイルを作りました。今回は「９を返す命令を書いてほしい」と、数字の文字列で指定します。その文字列を読み、対応するアセンブリを出力するプログラムが、この章で作るコンパイラです。

１この章で扱う問い

数字だけのソースコードを、実行できるプログラムに変えるには？

入力が９なら９を、４２なら４２を返すプログラムを作ります。入力が変わると、生成する命令のどこが変わるか。そして、変換するプログラムと、変換してできたプログラムは、それぞれいつ動くかを確かめます。

前提は、第１章の mov、ret、アセンブルとリンク、終了状態です。実行環境は同じコンテナを使います。実装にはＣ言語を使い、コードの読み方も必要な箇所で説明します。

２この章の理論

まず、受け付ける言語を決める

変換するには、入力をどう解釈するかが決まっている必要があります。この章の言語は、半角数字が１文字以上並んだ、０〜２５５の整数１個だけです。その意味を「この整数を返して終了するプログラム」と定めます。先頭の０は許し、009 も９として扱います。

空文字、空白、符号、足し算などはまだ受け付けません。たとえば 9+3 はエラーにします。０〜２５５という範囲は、シェルの終了状態で結果を欠けずに観察するための、この教材の制限です。ＣＰＵやコンパイラ一般がこの範囲しか扱えない、という意味ではありません。

数字の文字列を、命令の文字列へ変換する

入力 9 に対して、次のアセンブリを出力すれば目的を満たせます。

.intel_syntax noprefix
.text
.globl main
main:
    mov rax, 9
    ret
.section .note.GNU-stack,"",@progbits

前章と同じ準備用の指定を置き、main で９を rax に入れて戻ります。入力が４２なら、mov rax, 9 の９を４２に変えます。この言語では、入力によって変える箇所が一つだけなので、固定の文章に値を埋め込む方法でコード生成できます。

「コンパイラを作る」と「出力したプログラムを作る」

ここには２つのプログラムが登場します。一つは、Ｃで書いた自作コンパイラ。もう一つは、それが生成したコードから作る実験対象のプログラムです。既存の gcc を使う箇所も２回ありますが、入力と目的が違います。

この章では、Ｃで書いたコンパイラが、数字だけの小さな言語を扱います。コンパイラを書く言語と、コンパイラが受け付ける言語は別です。まだＣのプログラムを入力できるわけではありません。

同じ gcc が、Ｃにもアセンブリにも使える理由

gcc コマンドは、必要な道具を順番に呼び出し、コンパイル・アセンブル・リンクを手配する役も持っています。このような役割をドライバと呼びます。入力ファイルの種類とオプションによって、どの工程から始め、どこで止めるかが変わります。

Ｃのソースを渡すと、前処理（ヘッダの取り込みなど）、コンパイル、アセンブル、リンクを経て実行ファイルを作れます。一方、.s ファイルはすでにアセンブリなので、アセンブルから始めます。今回の環境では、機械語への変換は既存のアセンブラ、部品の結合はリンカが担当し、gcc がそれらを呼び出します。

入力とオプションによる、処理範囲の違い
コマンド処理と停止位置
gcc -S compiler.cＣからアセンブリを生成して止める。出力は compiler.s。
gcc -c compiler.cＣからアセンブリへの変換とアセンブルを行い、オブジェクトファイルで止める。出力は compiler.o。リンクはしない。
gcc -o /tmp/ch02-compiler compiler.cＣから始め、アセンブルとリンクまで行い、コンパイラ自身の実行ファイルを作る。
gcc -o /tmp/ch02-program /tmp/ch02-result.s生成済みのアセンブリから始め、アセンブルとリンクで実験対象の実行ファイルを作る。

-S はアセンブリの生成後、-c はオブジェクトファイルの生成後で止める指定です。小文字・大文字も区別します。-o は出力先を指定するもので、それ自体は停止する工程を決めません。途中のアセンブリが、毎回手元にファイルとして残るわけでもありません。

この章の自作コンパイラは「数字の文字列からアセンブリを出す」ところまでを担当します。その出力を実行ファイルにする工程は、gcc を窓口にして既存のアセンブラとリンカへ任せています。

実装を、入力・確認・出力に分けて読む

完成した実装は 実験用の compiler.c に用意しています。以下は、そのファイルを役割ごとに取り出したものです。最初に読む部分は、引数の数と空の入力を確認します。

int main(int argc, char **argv) {
    if (argc != 2) {
        fprintf(stderr, "使い方：コンパイラに０〜２５５の整数を１つ渡してください。\n");
        return 1;
    }

    const char *source = argv[1];
    if (source[0] == '\0') {
        fprintf(stderr, "入力が空です。\n");
        return 1;
    }

argc はプログラム名を含む引数の数、argv は引数の文字列を並べたものです。/tmp/ch02-compiler 42 なら、argv[0] がプログラム名、argv[1] が文字列 "42" となり、argc は２です。ここでは、この引数の文字列そのものをソースコードとして扱います。

source は入力文字列の先頭を指します。source[0] は最初の文字です。Ｃの文字列は末尾に終端を示す '\0' があるため、最初からこれなら入力は空です。'0' は数字の０という文字、'\0' は文字列の終端であり、別のものです。

fprintf(stderr, ...) はエラーの説明を標準エラー出力へ書きます。return 1 はコンパイラ自身を失敗の終了状態で終えます。引数の数を先に確認するので、存在しない argv[1] を読まずに済みます。

int value = 0;
for (int i = 0; source[i] != '\0'; i++) {
    if (source[i] < '0' || source[i] > '9') {
        fprintf(stderr, "半角数字だけを入力してください。\n");
        return 1;
    }
    value = value * 10 + (source[i] - '0');
    if (value > 255) {
        fprintf(stderr, "整数は０〜２５５の範囲で入力してください。\n");
        return 1;
    }
}

i を０、１、２と増やし、終端まで一文字ずつ読みます。|| は「または」で、数字の範囲外の文字なら終了します。数字だと確認した後、source[i] - '0' で文字を０〜９の数値へ変えます。数字の文字コードは連続しているので、文字 '4' と '0' の差は４になります。

value * 10 は、すでに読んだ数を十進数で一桁左へずらす操作です。そこに新しい一桁を足します。入力が 42 なら、次のように変わります。

文字から数値４２を組み立てる
読む文字更新前計算更新後
'4'００×１０＋４４
'2'４４×１０＋２４２

各桁を読むたびに２５５を超えていないか確認します。超えた時点で終了するため、長すぎる入力を最後まで巨大な整数として計算し続けることもありません。

printf(".intel_syntax noprefix\n");
printf(".text\n");
printf(".globl main\n");
printf("main:\n");
printf("    mov rax, %d\n", value);
printf("    ret\n");
printf(".section .note.GNU-stack,\"\",@progbits\n");
return 0;

printf は標準出力へ文字列を書きます。%d が value の十進数表記に置き換わり、\n が改行になります。Ｃの文字列の中に引用符を出すには \" と書くので、最後の行の出力には通常の "" が現れます。これらの関数を使うため、ファイル先頭には #include <stdio.h> を置いています。

最後の return 0 はコンパイラ自身が変換に成功したことを示します。生成したプログラムが返す値は、出力された mov の中にあります。入力９でも、コンパイラの終了状態は０、生成したプログラムの終了状態は９です。

コードを標準出力へ、エラーを標準エラー出力へ分けることで、生成物に説明文が混ざるのを防ぎます。また、入力の確認を終えるまでコードを出力しない構成にしています。

３ハンズオン

準備：コンテナ内で実験フォルダへ移動する

第１章で開いたコンテナのシェルをそのまま使えます。閉じていた場合は、コンテナ実行アプリを起動し、マック側のリポジトリで make -f docker.mk shell を実行して入り直してください。作成済みのイメージは、今回は作り直す必要がありません。

cd /workspace/textbook/new/labs/ch02

この cd は、コンテナ内で第２章のファイルがある場所に移動します。編集は、別のマック側ターミナルで次を実行すると、使い慣れたエディタで行えます。

nvim /Users/hatasatoki/Develops/compilerbook/textbook/new/labs/ch02/compiler.c

マックとコンテナは同じ教材ファイルを共有しています。以降のビルド・実行コマンドは、コンテナ側のターミナルで実行してください。

実験１：コンパイラを作り、出力を見る

gcc -std=c11 -Wall -Wextra -o /tmp/ch02-compiler compiler.c
/tmp/ch02-compiler 9
echo $?

１行目はＣの実装からコンパイラの実行ファイルを作ります。-std=c11 はＣの規格、-Wall -Wextra は警告を出す指定、-o は保存先の指定です。ビルドに成功してから次へ進みます。

２行目の実行前に：画面に出るのは数字９でしょうか、それとも命令の文字列でしょうか。３行目が表示する終了状態も予想してください。

実行後に開く：何を実行したか

画面には mov rax, 9 を含むアセンブリが表示され、その後の終了状態は０です。動いたのは変換する側のコンパイラで、出力された命令はまだ実行していません。

実験２：出力をファイルに保存し、そのプログラムを動かす

/tmp/ch02-compiler 9 > /tmp/ch02-result.s
echo $?
cat /tmp/ch02-result.s

> はシェルのリダイレクトです。通常なら画面に出る標準出力を、右側のファイルに保存します。このファイルはコマンド実行前に作成または空にされるため、再実行すると以前の内容を置き換えます。

直後の echo $? が０であることを確認します。cat は保存された内容を表示するだけで、実行はしません。ここで生成コードを読んだ後、次を実行します。

gcc -o /tmp/ch02-program /tmp/ch02-result.s
/tmp/ch02-program
echo $?

１行目は、今回はＣではなく生成済みの .s ファイルを入力にし、アセンブルとリンクで実行ファイルを作ります。２行目でその実行ファイルを起動し、３行目で終了状態を表示します。成功して作成されたことを確認してから実行し、echo $? は間に別のコマンドを挟まずに実行してください。

実行後に開く：２つの終了状態

生成したプログラムの終了状態は９です。前の０は「コンパイラの変換成功」、今回の９は「生成したプログラムの返した値」です。$? は常に直前に動かしたコマンドの状態なので、何を直前に動かしたかとセットで読みます。

実験３：入力だけを変える

入力を４２にしたとき、生成ファイルのどの行が変わり、どの行が変わらないかを先に予想します。コンパイラ自身は変更していないので、compiler.c の再ビルドは不要です。

/tmp/ch02-compiler 42 > /tmp/ch02-result.s
cat /tmp/ch02-result.s
gcc -o /tmp/ch02-program /tmp/ch02-result.s
/tmp/ch02-program
echo $?
観察後に開く：変わる箇所と再生成が必要なもの

mov rax, 9 が mov rax, 42 に変わり、終了状態は４２です。入力を変えたらアセンブリの生成と、そのアセンブル・リンクをやり直します。コンパイラの実装を変えた場合には、さらにその前のコンパイラ自身のビルドも必要です。

実験４：言語の境界を確かめる

9+3 は、９として扱われるでしょうか、１２になるでしょうか、それとも拒否されるでしょうか。入力確認のループを根拠に予想します。

/tmp/ch02-compiler '9+3' > /tmp/ch02-rejected.s
echo $?
cat /tmp/ch02-rejected.s

引用符はシェルに一つの文字列として渡す指定で、コンパイラが受け取る文字列自体には含まれません。今回の無効な入力の後は、アセンブル・リンクへ進みません。

観察後に開く：エラーが画面に残る理由

半角数字だけを入力するようエラーが出て、終了状態は１です。数字９を読んだ後、+ で拒否します。コード生成まで進まないのでファイルは空です。> が保存するのは標準出力なので、標準エラー出力のメッセージは画面に残ります。

同じ実行コマンドの引数を 255、256、'' に変え、受け付ける境界を確かめてください。成功した入力について生成コードを見て、失敗した入力については終了状態と説明を確認します。

この章の区切りは、入力・生成コード・実行結果の対応を説明でき、コンパイラ自身と生成したプログラムの終了状態を区別できたときです。

４理解チェック

入力が 007 なら、何が出力されるか？

解説を読む

数値は７になり、mov rax, 7 が出力されます。０、０、７を順に読んだ計算結果を %d で出すため、入力の見た目をそのままコピーしてはいません。

コンパイラ実行後の $? と、生成したプログラム実行後の $? は、それぞれ何を表すか？

入力０をコンパイラに渡して変換し、生成したコードをビルドして実行したとします。どちらの実行直後も echo $? は０を表示しました。それぞれの０が何を示すか説明してください。

解説を読む

コンパイラ実行後の０は、入力の変換に成功して正常に終了したことを示します。生成したプログラム実行後の０は、そのプログラムが入力に対応する値０を返して終了した結果です。$? は直前に実行したコマンドの終了状態なので、同じ数値でも、どのプログラムの何を確認しているかを区別して読みます。

入力を４２に変えたのに、実行結果が９のままなら？

解説を読む

生成した .s の中身、そこからのビルドの成功、実行したファイルのパスを順に確認します。アセンブリだけ更新しても、既存の実行ファイルは変わりません。コンパイラのソースを変えたなら、その再ビルドも確認します。

なぜ 9+3 を扱うには、数字の置き換えだけでは足りないか？

解説を読む

９と３という数と、足すという操作を区別して理解する必要があるからです。今の処理は入力全体を整数１個として扱い、+ を拒否します。次章ではまず文字列を数や記号の単位に分け、その先で構造と命令への変換を学びます。
