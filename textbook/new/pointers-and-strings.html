第１０章

ポインタと文字列

値そのものではなく、値のある場所を渡す。

第７章では、コンパイラが変数の保存場所を決めました。今回は、その「場所」をプログラム内で扱います。同じ場所を指す二つの名前、連続した配列、文字列の終わりを、メモリと命令の対応から見ていきます。

１この章で扱う問い

アドレスを渡すと、別の関数から元の値を変更できるのはなぜか？　文字列はどこまで読めばよいのか？

第７章の b=a; は、その時点の値をコピーしました。今回は p=&a; として、a の場所を渡します。コピーするものが値なのか場所なのかで、その後の変更の意味が変わります。

前提は第７章のメモリの読み書き、第８章の引数、第９章のビット幅です。本章は既存のＣコンパイラと短いアセンブリを使う観察実験です。自作言語へ型・配列・文字列の構文を一度に実装する章ではありません。最後に、自作コンパイラへ追加するなら何の情報が必要かを整理します。

２この章の理論

値、場所、その場所を入れる変数を分ける

int64_t a = 7;
int64_t *p = &a;
int64_t *q = p;

int64_t は６４ビットの符号付き整数型です。int64_t *p は「その型の値を指すポインタを入れる変数 p」という宣言です。ポインタは、対象の場所を指す値として使います。&a は a のアドレスを得る式で、これを p に入れています。

*p は、p が指す場所の対象を使う式です。printf などへ値として渡せば読み出し、*p=42; と書けばその場所へ４２を書き込みます。このように、場所を通して対象を使う操作を間接参照と呼びます。宣言中の＊と、式の中の＊では役割が違います。式でも二つの値の間に書く a*b は掛け算です。

p 自身も変数なので、p を保存している場所があります。&p はその場所、p は中に入っている「a を指す値」、*p は指した先の a です。これらを一つの「アドレス」という言葉だけでまとめず、何の場所かを区別します。

q=p はアドレスの値をコピーします。a の７を別の整数変数へコピーしたわけではないため、q を通して書き込むと p から見える値も変わります。同じ対象へ複数の経路からアクセスできる状態を、別名参照と呼ぶことがあります。

渡した場所を、機械語で読み書きする

第８章と同じ規約で、第１引数は rdi、第２引数は rsi に入ります。ポインタを第１引数に渡すと、rdi は値７ではなく a のアドレスを持ちます。用意した関数の主要な命令は次のとおりです。

read_value:
    mov rax, [rdi]
    ret

write_value:
    mov [rdi], rsi
    ret

read_value(p) は、rdi が指す場所から８バイトを読んで rax で返します。write_value(p,42) は、rsi に渡された４２を、rdi が指す場所へ８バイト書きます。角括弧が、そのアドレスのメモリを使うことを示しています。write_value のＣ側の戻り値の型は void で、返り値は利用しません。

引数としてコピーされるのは、今回も値です。ただし、その値がアドレスなので、呼び出し先が元の対象へ届きます。「Ｃは変数そのものを関数へ移す」という意味ではありません。また、関数へ渡したポインタ自身を書き換えることと、指す先を書き換えることも別です。

ポインタに１を足すと、何バイト進むか

int64_t values[] = {10, 20, 30};
int64_t *p = values;

配列は、同じ型の要素を連続して置くものです。ここでは８バイトの整数が３個並びます。p = values の右側の配列は、先頭要素を指すポインタへ変換されます。配列そのものとポインタ変数が同じ物になったわけではありません。

Ｃの p+1 は「次の要素」を指します。この型なら８バイト先です。char * なら１要素が１バイトなので１バイト先になります。添字の p[1] は *(p+1) と同じ意味です。

機械語の mov rax, [rdi+8] の８は、バイト単位の距離です。Ｃのポインタ型をＣＰＵが調べて８へ変換するのではなく、コンパイラが要素の型の幅を使って命令を作ります。一般の添字なら、必要に応じて添字を要素幅で掛けます。

sizeof values はこの配列全体の２４バイト、sizeof *p は１要素の８バイトです。sizeof p はポインタ変数自体の幅であり、先にある配列の長さではありません。通常のポインタの値だけから、その先に何個の要素があるかはわかりません。

Ｃの文字列は、０で終わる文字の配列

char text[] = "ABC";

この配列には A、B、C に加え、最後に値０の１バイトが入ります。これを終端のヌル文字と呼び、Ｃでは '\0' と書きます。数字の文字 '0' とは違います。今回の環境で A、B、C の値はそれぞれ６５、６６、６７、終端は０です。

strlen(text) は先頭から最初の０までを調べ、終端を含めずに３を返します。sizeof text は配列の領域全体なので４です。途中に０を書けば文字列としての終わりは早まりますが、配列の領域が縮むわけではありません。

これは「最初の０まで読む」という文字列処理の約束です。ＣＰＵの一般的なメモリ読み出しが、０を見つけると自動で止まるわけではありません。また、strlen が数えるのはバイト数で、日本語などの表示上の文字数と一致するとは限りません。本章は１文字１バイトの A・B・C に絞ります。

アドレスを作る命令と、そこを読む命令

教材の message_address は、アセンブリ側に置いた文字列の場所を返します。

message_address:
    lea rax, [rip + .Lmessage]
    ret

.section .rodata
.Lmessage:
    .asciz "ABC"

.rodata は読み取り専用のデータを置く領域、.Lmessage はその場所の名前です。.asciz は指定した文字のバイト列に０を付けて配置する、アセンブラへの指示です。この３行は命令として実行されません。ファイル内にデータを用意します。

lea は、角括弧内のアドレスを計算してレジスタに入れます。mov rax, [rdi] のようにその場所の値を読む命令ではありません。この例の rip は命令の位置に関係するレジスタで、RIP 相対という形で、次の命令の位置から文字列までの距離を使って場所を求めます。距離の調整にはアセンブラやリンカーが関わります。

返すのは３文字を詰めた値ではなく、先頭の A のアドレスです。Ｃ側がそのポインタを printf の %s に渡すと、表示処理が文字列を読みます。別の first_byte は movzx eax, BYTE PTR [rdi] で先頭の１バイトだけを読み、ゼロ拡張して返します。場所を得る段階と、そこを読む段階が別であることを確認します。

書き換えてよい場所か、まだ使える場所か

char text[]="ABC"; は書き換え可能な配列を用意するので、本章ではその中へ０を書けます。一方、Ｃの文字列リテラル "ABC" 自体を書き換えることはできません。今回アセンブリで .rodata に置いたデータも書き換えず、const char * として受け取ります。const は、このポインタを通して文字を書き換えないことを型に表しています。

アドレスを持っていても、いつでも読み書きできるわけではありません。ローカル配列の存続期間が終われば、それを指すポインタを返して使い続けることはできません。今回の .rodata の文字列はプログラムの実行中ずっと存在するため、message_address から戻った後にも読めます。

配列のポインタ計算は、同じ配列の範囲と、その末尾の一つ先までに限ります。末尾の一つ先のポインタは比較などに使えますが、そこから値を読んではいけません。値の幅が８バイトなら、８バイト全体が有効な対象内に収まる必要があります。場所が数値として計算できることと、Ｃの操作として正しいことは別です。

ヌルポインタは有効な対象を指さないポインタで、ヌル文字は値０の文字です。似た名前でも別の概念です。また、終端のない配列を strlen や %s に渡す実験、無効なポインタの間接参照、読み取り専用データの書き換えは行いません。安全に観察できる範囲で確かめます。

自作コンパイラへ戻って考える

第７章の変数ノードは、決まった場所から値を読むだけでした。アドレスを扱うなら、「値を読む」の前段階に「その対象の場所を求める」処理が必要です。代入の左側は場所、右側は値を必要とします。&a では場所をそのまま結果にし、*p では p の値を場所として読み書きします。

さらに、ポインタが何を指す型かを管理しないと、p+1 の１要素が何バイトかわかりません。文字列を扱うなら、命令とは別にデータを置き、名前を付けてそのアドレスを生成する必要があります。これらが、構文だけを追加しても足りない理由です。第１１章では、命令とデータがファイルや実行中のメモリへどう配置されるかを広げて見ます。

３ハンズオン

準備：メモリを観察するプログラムを作る

これまでと同じリナックスのコンテナ内で実行します。まだ入っていなければ、マック側のリポジトリで make -f docker.mk shell を実行してください。

cd /workspace/textbook/new/labs/ch10
gcc -std=c11 -Wall -Wextra -o /tmp/ch10-inspect inspect.c memory.s

inspect.c が値を用意して表示し、memory.s が短い機械語の関数を提供します。gcc が両方を処理してリンクします。今回は自作コンパイラではなく、観察用プログラムをビルドしています。

実験１：ポインタを通して、元の変数を書く

実行前に：p と q がともに a を指すとき、write_value(q,42) の後で a・*p・*q はそれぞれ何になるか予想してください。

/tmp/ch10-inspect address

address は実験名です。表示されるアドレスは、printf の %p を使っています。アドレスの具体的な数値は実行ごとに変わることがあるので、数値を暗記せず、どの表示同士が一致するかを見てください。

実行後に開く：場所は共有され、値は４２に変わる

a の場所と p が指す場所が一致します。一方、p 自身の場所は別です。最初に機械語で読める値は７、書き込み後は a・*p・*q のすべてが４２です。q へ４２を入れたのではなく、q が指す対象へ書きました。

実験２：「＋１」が１バイトとは限らないことを見る

values は８バイトの整数３個です。p[1]、*(p+1)、機械語の [rdi+8] は同じ場所を読むか、予想します。

/tmp/ch10-inspect array
実行後に開く：三つとも２０

１要素は８バイト、配列全体は２４バイトです。どの読み方でも２番目の要素２０になります。また、Ｃの (p+1)-p は１です。ポインタ同士の差も、ここではバイト数ではなく要素数を表します。

実験３：文字列の長さと、配列の大きさを分ける

char text[]="ABC"; の後で text[1]='\0'; とします。文字列の表示、strlen の結果、sizeof の結果、text[2] の値を予想してください。

/tmp/ch10-inspect string
実行後に開く：短くなったのは、終端までの範囲

最初は表示が ABC、配列４バイト、長さ３です。変更後は表示が A、配列は４バイトのまま、長さは１になります。text[2] の C は消えずに残ります。文字列処理が最初の０で止まるため、表示されないだけです。

さらに試すなら、マック側のエディタで textbook/new/labs/ch10/inspect.c の text[1]='\0' を text[1]='X' に変えます。末尾の０は残るため、表示は AXC、長さは３になるはずです。同じ関数の assert にある strlen(text) == 1 も strlen(text) == 3 に変え、準備の gcc コマンドでビルドし直してから、string の実験を実行します。assert は期待値の検査なので、新しい実験に合わせています。試した後は両方を戻し、再ビルドしてください。

実験４：関数から文字列の場所を受け取る

message_address が返すのは、文字列そのものを詰めた整数でしょうか、それとも先頭の場所でしょうか。first_byte の結果も予想します。

/tmp/ch10-inspect literal
実行後に開く：場所を受け取り、読む側が用途を決める

文字列として表示すると ABC、先頭１バイトを整数として読むと６５です。同じ場所を渡しても、%s は０までの列として、first_byte は先頭の１バイトとして読みます。message_address は読み取り専用データの場所を返し、そのデータは関数が戻った後も残ります。

実験５：ファイル内の文字データを見つける

gcc -c memory.s -o /tmp/ch10-memory.o
objdump -s -j .rodata /tmp/ch10-memory.o

１行目はアセンブルだけ行い、オブジェクトファイルを作ります。２行目の -s は内容のバイト表示、-j .rodata は対象の領域の指定です。メモリに読み込んで関数を実行しているのではなく、ファイルのデータを観察します。

観察後に開く：41424300 が ABC と終端に対応する

１６進の 41 42 43 00 が見つかります。順に十進６５・６６・６７・０です。最後の０は画面に見える文字ではありませんが、文字列の終わりを示す実際の１バイトです。

すべての教材を元の状態に戻したら、bash check.sh で確認できます。検証スクリプトは最適化なし・ありの両方で値を確認し、オブジェクト内の終端も調べます。プログラム内の assert は、予想した条件が満たされるかを検査し、違えば停止するためのものです。

４理解チェック

p と &p と *p は、何を表すか？

解説を読む

p はポインタ変数の中の値、&p はポインタ変数自身の場所、*p はその値が指す先の対象です。p が a を指していれば、*p を読む操作は a の値を読みます。

q=p の後に *q を変えることは、第７章の b=a と同じか？

解説を読む

コピーする値の意味が違います。q=p は場所を指す値をコピーするため、両方から同じ対象へ届きます。整数の b=a は整数値のコピーなので、その後に b を変えても a は変わりません。

mov rax, [rdi+8] の８を、ＣＰＵが型から選んだのか？

解説を読む

いいえ。コンパイラまたはアセンブリを書いた人が要素幅に基づいて８を指定しています。命令にはＣのポインタ型がそのまま残っているわけではありません。

文字列の途中へ０を書くと、配列の残りは削除されるか？

解説を読む

削除されません。最初の０を終端とする処理が、その先を文字列として読まなくなります。配列の範囲内なら、残る要素は添字で個別に読めます。

lea rax, [rip + .Lmessage] は、A の値６５を返すか？

解説を読む

返すのは A が置かれた場所です。lea はアドレスを求める命令です。６５を得るには、その場所の１バイトを別の読み出し命令で読む必要があります。

関数内のローカル配列のアドレスを返せば、文字列を残せるか？

解説を読む

その配列の存続期間が関数から戻った時点で終わるなら、返したポインタで読み続けることはできません。本章の message_address が返すのはローカル配列ではなく、実行中ずっと存在する静的なデータの場所です。
