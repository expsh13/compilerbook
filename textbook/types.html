この名前は、何を表している？

Cの型の構文

配列・ポインタ・関数を、小さな型の部品としてつなぐ。
名前から順番に読むと、長い宣言もほどける。

この章の到達点カッコの位置で変わる型を図にでき、関数ポインタを受け取り返す宣言まで説明できる。

原書「Cの型の構文」に対応。宣言の説明はC11を基準とし、メモリの大きさはLinux・x86-64を想定する。図・コード・操作欄は本教材独自のもの。

01宣言の見た目と、型の構造を分ける

ここまでは、変数や関数を使う意味を学んできた。最後は、宣言の文字列から「それは何で、何を指し、何を返すのか」を読み取る練習をする。機械語を増やす章ではなく、コンパイラが型を理解する入口を整理する章だ。

まず、この２行の違いを読めるようになる
int *items[3];
int (*row)[3];

どちらにもint・*・[3]があるが、items自身は配列で、row自身はポインタ。名前の前だけを見て「両方ともintへのポインタ」と読んではいけない。

原書では型のつながりを、配列は [3]、ポインタは *、関数は func(引数の型) と短く書く。たとえばitemsは [3] * int、rowは * [3] int。これは説明用の記法で、Cの宣言としてそのまま書くものではない。

コンパイラ内部でも、型の種類と、次につながる型を持つデータ構造で表せる。配列には長さ、関数には引数の型の一覧も必要になる。

02名前から、カッコの境界を守って読む

読み始める場所は宣言している名前。そこから、その名前を囲む宣言子を内側から外側へたどる。「宣言子」は、名前と *・[]・() の組み合わせのことだ。

  1. 名前を見つける。
  2. 同じカッコの範囲で、右に付く [数] や (引数の型) を先に読む。
  3. 次に、その範囲の左側の * を近いものから読む。
  4. グループを作るカッコの内側を読み終えたら、外へ出て続ける。
  5. 最後に int などのベースの型につなぐ。
同じ記号でも、カッコが境界になる
int *items[3];    // items → [3] → * → int
int (*row)[3];    // row   → *   → [3] → int

itemsは右の[3]が先なので「３要素の配列」。rowは (*row) の内側で、まず*を読む。外側の[3]まで先に飛び越えないので「配列を指すポインタ」になる。

型が違うと、置き場と使い方も違う

宣言した型に合う値を用意する
int a = 10, b = 20, c = 30;
int *items[3] = {&a, &b, &c};

int values[3] = {10, 20, 30};
int (*row)[3] = &values;

// どちらの式も20を表す
// *items[1]   : ２番目のポインタが指すintを読む
// (*row)[1]   : 指す先の配列の２番目のintを読む

03関数と、関数を指すポインタを分ける

右側の (引数の型) は「関数」を表す。関数自身なのか、関数へのポインタなのかも、読む順番で決まる。

関数の宣言と、関数ポインタの宣言
int *make(void);      // make → 関数 → ポインタ → int
int (*apply)(int);    // apply → ポインタ → 関数 → int

make(void) は引数なし。(*apply) は読み順をまとめるカッコで、その後ろの (int) は引数の型を指定するカッコ。同じ丸カッコでも役割が違う。

宣言したポインタに関数を入れ、実際に呼ぶ
int increment(int n) {
    return n + 1;
}

int main(void) {
    int (*apply)(int) = increment;
    return apply(12);             // 13を返す
}

applyにはincrementを指す関数ポインタを入れる。apply(12) でその関数を呼べる。(*apply)(12) と書くこともできる。宣言の (int) は「引数の型」、呼び出しの (12) は「渡す値」だ。

この教材はC11の宣言を基準にする。C11では、関数の宣言 int f(); は引数の型・個数を指定していない。引数なしを明確に表す例には int f(void); を使う。

04ネストした宣言を、内側と外側に分ける

カッコが重なったときは、内側に残る「まだ決まっていない型」へ、外側の型をはめると整理できる。原書の分解方法を、２要素の配列で試す。

intを受け取る関数へのポインタを２つ並べる
void (*handlers[2])(int);

handlers[0]もhandlers[1]も関数へのポインタなので、有効な関数を入れた後は handlers[0](7) のように呼べる。宣言だけで関数本体が作られるわけではない。

コンパイラにとっては、型の部品をつなぐ処理

ベースの void を読み、宣言子の構造から配列・ポインタ・関数を組み合わせる。関数なら引数の型もそれぞれ読む。最後に、名前handlersとできあがった型を対応付ける。第２章で式からASTを作ったのと同様に、ここでは宣言から型の構造を作る。

構文として読めても、許されない型はある。Cでは関数そのものの配列や、配列そのものを返す関数は作れない。関数へのポインタを配列にする、配列へのポインタを返す、という形なら表現できる。

05signalの宣言をほどく

原書の最後の大きな例は、signalの宣言。ここではシグナルの動作ではなく、関数の引数と返り値の型に絞って読む。

signalの宣言
void (*signal(int, void (*)(int)))(int);

まず signal の直後に引数のカッコがあるので、signal自身は関数。引数は２つあり、第１引数はint、第２引数は void (*)(int)。第２引数の型は、前の節の関数ポインタから変数名を省いた形だ。

次に左の*を読み、signalが返すものはポインタだとわかる。グループの外にある (int) と、ベースのvoidを合わせると、返すポインタも「intを受け取り、値を返さない関数」を指す。

同じ型に名前を付けると、役割が見える

typedefで、関数ポインタ型に別名を付ける
typedef void (*Handler)(int);

Handler signal(int number, Handler handler);

typedef は、この型をHandlerという名前でも呼べるようにする宣言。関数を呼んだり、Handlerという変数を作ったりはしない。この書き換えで、signalは「intとHandlerを受け取り、Handlerを返す関数」だと読める。

Cの宣言は、使うときの式の形と対応している。たとえば int *items[3]; では、有効な添字iとポインタの値を用意すれば *items[i] の型がintになる。ただし型が合うことと、初期化済み・範囲内で安全に使えることは別。

06宣言を１つずつ読み進める

用意した宣言を選び、「次を読む」で進める。今読んでいる記号と、型の図に足される箱を対応させよう。ここで進むのは宣言の読み取りであり、プログラムの実行ではない。

0 / 4

宣言を切り替えると最初に戻る。選択肢の宣言だけを追う教材で、任意のCコードを解析するツールではない。

int *items[3];

まず宣言する名前を見つけよう。

型の図は、読むにつれて左から増える。

07理解を確かめる

まず「名前自身は何か」を答え、その後で要素・指す先・返り値をたどる。

int **p; のp自身はint？

p自身はポインタ。指す先もポインタで、そのさらに先がint。型のつながりはポインタ → ポインタ → int。

int grid[2][3]; は、３要素の配列が２つ？

その通り。gridは２要素の配列で、各要素は３要素のint配列。配列２ → 配列３ → intの順に読む。

int (*f)(void); と int *f(void); は同じ？

前者のfは関数へのポインタで、指す関数はintを返す。後者のfは関数で、intへのポインタを返す。どちらも引数はない。

void (*table[4])(int); に並ぶのは関数本体？

関数へのポインタが４つ並ぶ。それぞれの指す関数はintを１つ受け取り、値を返さない。

関数の引数にあるvoid (*)(int)には名前がないけれど読める？

読める。名前を省いて型だけを表している。ポインタ → 関数（intを受け取る）→ void。

int *a, b; は両方ともポインタ？

aだけがintへのポインタで、bはint。intという指定は共有するが、*はaの宣言子に属する。

int a[][]; と書けば、２次元配列を宣言できる？

そのままでは不可。外側の配列の要素となる配列の大きさが不明になる。たとえば extern int a[][3]; なら外側の長さを省略できる。

関数の仮引数の配列は、普通の配列変数と同じ？

void use(int a[3]); の仮引数aの型は、intへのポインタに調整される。３要素の配列を値として丸ごと受け取る宣言ではない。この章のメモリ比較は通常の変数の宣言を対象にしている。

原書の練習表は型を組み合わせて読む練習も含むが、実際のCでは許される型に制約がある。ここでは固定長の配列とプロトタイプのある関数を中心にし、const・可変長配列・複雑な仮引数の規則は別の範囲とする。
