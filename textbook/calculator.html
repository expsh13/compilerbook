01計算する命令をつくる

入力の 8 + 3 * 2 は、最初はただの文字列。コンパイラはそこから演算のまとまりを読み取り、あとで実行すると14になるプログラムを出力する。この段階の出力はアセンブリの文字列だ。

最初の２段階は、出力の形をつかむためにある

整数１個なら「その値をRAXに入れて返す」で足りる。加減算だけなら、最初の値をRAXに入れ、続く数を足し引きできる。8 + 3 - 2 なら、実行時のRAXは 8 → 11 → 9 と変わる。

加減算だけの段階で出す命令の例
mov rax, 8
add rax, 3
sub rax, 2
ret

乗算を足すと、文字の順番通りの計算では困る。8 + 3 * 2 をそのまま左から処理すると22になるため、まず 3 * 2 をひとまとまりとして認識する必要がある。

02文字列を意味のある単位へ

トークンは、後の処理（ここでは主に、抽象構文木を作る構文解析）が１単位として扱う数や記号。字句解析（トークナイズ）は、文字を読み、トークンの種類や値を取り出す作業だ。12 は「1」と「2」の２文字でも、整数のトークンとしては１個になる。

<= は２文字で１つの演算子。１文字の < より先に、２文字で一致するかを確かめる。空白はトークンを読む際に飛ばすので、12 34 を勝手に 1234 に連結することはない。

トークンに持たせる情報何に使う？
種類整数・記号・入力の終わりを区別する。
値整数の文字列を、数値として扱えるようにする。
元の位置・長さ２文字の記号を識別し、入力のどこが間違っているか示す。
次のトークンへのつながり順番に読む。原書は連結リスト、観察欄は配列を使う。

エラーは「次に何を期待したか」と一緒に示す

入力の位置を保持していると、ここまで案内できる
8 + * 2
    ^
数値または「(」が必要です。

* 自体は有効な記号なので字句解析は通る。けれど + の直後には値になる式が必要なので、構文解析で止める。

consume と expect は、構文解析でトークンを読み進めるために、自作コンパイラに用意する補助関数の名前。C言語のキーワードではない。「合う」とは、今見ているトークンが、期待した記号などと一致することを指す。

  • consume：一致すれば、そのトークンを読み取って次へ進む。一致しなければ、読み取り位置を変えずに「一致しなかった」と呼び出し元へ返す。
  • expect：一致すれば、そのトークンを読み取って次へ進む。一致しなければ、必要なトークンがないためエラーにする。

最後にEOFまで読んだことも確認し、余った入力を見落とさない。

概念の参照：LLVMの字句解析の解説。図とエラー例は本教材独自のもの。

03式のまとまりを木にする

トークン列には順番があるが、どの２つを掛けるかはまだ明示されていない。抽象構文木（AST）は「この演算の左と右は何か」をつなげたデータ。葉に数、枝の分岐点に演算子を置く。

左の木では、足し算の右側が「掛け算の木」になっている。足すには左右の値が必要なので、右の 3 * 2 の結果を先に用意する。木のいちばん上は最後に行う演算だ。

優先順位と、同じ強さの演算のまとまり方

優先順位は「掛け算が足し算より強く結びつく」という規則。結合規則は、同じ強さが続いたときのまとまり方。16 - 6 - 2 は左結合なので (16 - 6) - 2、結果は8。16 - (6 - 2) なら12になる。

ASTを作る段階で決めるのは構造。ここで答えまで計算しなくてもよい。この教材のコード生成は、数や演算をそのまま命令列にする。

概念の参照：LLVMの構文解析とASTの解説。

04文法を関数にする

ここからは、前の節で見た抽象構文木（AST）を、トークン列からどう作るかを考える。入力は数や記号に分けられたトークン列、出力は「どの演算が、どの式を左右に持つか」を表す木だ。

その処理を、コンパイラの中に作る３つの関数で分担する。expr()・mul()・primary() はその関数名で、生成されるプログラムの関数ではない。返すのは計算結果ではなく、その部分を表すASTのノード。ノードを受け取ると、そこにつながる木全体を扱える。

小さなまとまりを作り、それを大きなまとまりにつなぐ

まず、最も小さいものを読む役から見る。関数名は原書の実装で使う名前であり、C言語に最初から用意されている機能ではない。

関数何をするか何を返すか
primary()
数・カッコの担当		数なら、そのトークンを読んで数のノードを作る。( なら、中の式を expr() に任せ、続く ) を確認する。数のノード、またはカッコ内の式を表す木。
mul()
掛け算・割り算の担当		まず primary() に左側を読んでもらう。続きが * または / なら、右側も primary() に読んでもらい、演算子のノードでつなぐ。続く限り繰り返す。掛け算・割り算の木。その演算子がなければ、最初に受け取った木をそのまま返す。
expr()
足し算・引き算の担当		まず mul() に左側を読んでもらう。続きが + または - なら、右側も mul() に任せ、演算子のノードでつなぐ。続く限り繰り返す。足し算・引き算の木。その演算子がなければ、最初に受け取った木をそのまま返す。

実際の入り口は expr()。そこから mul()、さらに primary() を呼ぶ。呼び出しは大きなまとまりから小さなまとまりへ進み、できた木は逆向きに返ってくる。

３つの関数は「次に読むトークンの位置」を共有する。読んだ分だけ位置を進めるので、呼び出した関数が戻ったら、その続きから読める。担当外の演算子は読まずに残し、それを扱う呼び出し元に任せる。

8 + 3 * 2 を読むと、どの関数が何を返す？

固定式 8 + 3 * 2 の構文解析を追う。１操作は、関数の呼び出し・トークンの読み取り・木の組み立て・関数からの戻りなど。CPUの１命令ではない。

0 / 23

開始前。まずexpr()を呼ぶ。

手順と全体図を読む
  1. expr() が左側を mul() に任せる。mul() は primary() から「8」のノードを受け取る。次は + なので、それを読まずに「8」を返す。
  2. expr() が残っていた + を読む。右側を作るために、もう一度 mul() を呼ぶ。読み取り位置は今度は「3」だ。
  3. mul() は primary() で「3」を読み、続く * を自分で読む。さらに primary() で「2」を読み、左右に3と2を持つ「*」の木を作って返す。ここでは6を計算して返すわけではない。
  4. expr() が、左の「8」と右の「3 * 2の木」を + のノードでつなぐ。これで式全体のASTができる。

足し算の右側を読むときに mul() を呼ぶから、3 * 2 がひとまとまりで返ってくる。この呼び分けによって、掛け算・割り算が足し算・引き算より強く結びつく木になる。

カッコの場合は、primary() が ( を読んだあとで expr() を呼び、カッコ内の式を丸ごと読んでもらう。戻ってきたら expect で ) を確認する。こうして関数を呼び直すので、カッコが入れ子になっていても同じ仕組みで読める。このように、文法の規則に対応する関数を呼び合って木を作る方法が再帰下降構文解析だ。

この分担を、文法の記号で短く書く

文法は「どんなトークンの並びを式として認めるか」という約束。ここまでの３つの関数の読み方を、EBNFという文法の表記でまとめると次のようになる。num は整数トークンを表す。

四則演算とカッコの文法（EBNF）
expr    = mul (("+" | "-") mul)*
mul     = primary (("*" | "/") primary)*
primary = num | "(" expr ")"

１行目は「まず mul を読み、そのあと『+ または - と、次の mul』を０回以上読む」という意味。足し算・引き算がない式も、最初の mul だけで認められる。

| は「どちらか」、引用符の外の * は「直前のまとまりを０回以上繰り返す」。引用符付きの "*" は、入力に現れる掛け算記号そのものだ。引用符の外のカッコは文法のまとまりを表し、"(" と ")" は入力のカッコを表す。

expr など、別の規則を参照する名前を非終端記号という。"+" など入力に現れる記号や、数を表す num は、この文法の終端にあたる。文法中の = は規則の定義であり、Cの代入ではない。

左結合は、できた木を左側に付け直して作る

expr() の考え方を表す疑似コード
左の木 = mul()
次が + または - の間、繰り返す:
    演算子を読む
    右の木 = mul()
    左の木 = 演算子(左の木, 右の木)
左の木を返す

この更新で、16 - 6 の木が次の引き算の左側になる。mul() が自分の担当外の + を見たら、それを消費せずに戻ることも大切だ。

05途中結果をスタックへ

木の形がわかっても、右側を計算している間、左側の値をどこかに残す必要がある。第１章で戻り先を保存した同じスタックの仕組みを、今度は計算途中の値に使う。

生成するコードには約束を１つ置く。「式１つを計算すると、スタックに結果を１つ残す」。左の式も右の式もこの約束を守れば、取り出して演算し、結果を積むだけで組み合わせられる。

木をたどる順序が、そのまま命令を出す順序になる

数のノードでは値を積む命令を出す。演算子のノードでは左の木 → 右の木 → 演算の順にコードを出す。後から積んだ右の値が先に出てくるので、引き算・割り算では取り出し順を間違えない。

減算：左の値 − 右の値
pop rdi       # 右の値
pop rax       # 左の値
sub rax, rdi
push rax      # 結果を１つ戻す
符号付きの割り算
pop rdi       # 割る数
pop rax       # 割られる数
cqo
idiv rdi
push rax      # 商を戻す

idiv rdi はRDXとRAXをつないだ値をRDIで割る。cqo はRAXの符号をRDX側へ伸ばし、割り算の入力を整える。商はRAX、余りはRDX。ここで使う整数の割り算は小数部分をゼロ方向に切り捨てるので、-7 / 2 は -3 になる。

式全体の結果を最後に pop rax で取り出すと、一時的に積んだ分がすべてなくなり、RSPは元に戻る。その後の ret が取り出すのは、計算結果ではなく呼び出し元への戻り先。前章のスタックの話につながる。

06符号と比較を加える

ここまでは、四則演算とカッコを扱うコンパイラを作ってきた。この節では、数の前に符号を付ける式と、２つの値を比較する式も扱えるようにする。

追加したい式実行すると何が得られる？
-3、+3符号を反転した値、またはそのままの値。この例では−3と3。
3 < 8、3 == 8条件が成り立てば1、成り立たなければ0。この例では1と0。

やることは今までと同じで、式を読んでASTを作り、その木から命令を出す。以下の計算や比較は、その命令を実行するときに行われる。構文解析中に答えを求める話ではない。

① 符号：−3を「0から3を引く」と考える

8 - 3 の - は、左の8から右の3を引く。いっぽう、-3 には左の数がなく、右の3の符号を反転する。この違いを、トークンを読む構文解析の段階で見分ける。

そこで、数やカッコを読む primary() の手前に、符号を読む unary() を追加する。mul() は、これまでの primary() の代わりに unary() を呼ぶ。unary() は先頭の符号があれば読み、その後の数やカッコを primary() に任せる。

-3 を読んだら、左に0、右に3を持つ「引き算の木」を作る。そうすれば、すでに作った減算の命令生成をそのまま使える。+3 なら、3のノードをそのまま返せばよい。符号がない場合も、読んだ木をそのまま返す。

値１つを受け取る符号の操作を「単項演算」、２つを受け取る引き算などを「二項演算」という。この段階の文法で読める単項の符号は１つまで。-(-3) は読めるが、--3 は扱わない。

② 比較：「成り立つ？」の答えを0か1にする

比較も、足し算と同じように左右の式を持つASTにする。違うのは、結果が「真なら1、偽なら0」になること。3 < 8 なら1、3 == 8 なら0になる。== は「等しいか」を調べる記号だ。

結果を整数にそろえれば、比較でも前節の「式１つにつき、スタックに結果を１つ残す」という約束を守れる。左右の値を取り出し、比較して0か1を作り、それをスタックに積めばよい。

「等しいか」を調べる命令は、どう作る？

以下は == のために出す命令。左右の式の値は、前節と同じく左、右の順でスタックに積んであるものとする。

等しいなら1、違うなら0をスタックに残す（Intel記法）
pop rdi        # 右の値を取り出す
pop rax        # 左の値を取り出す
cmp rax, rdi   # 比較の状態をフラグに記録する
sete al        # 等しければ1、違えば0をALに入れる
movzx rax, al  # RAX全体を、その0か1にそろえる
push rax       # 比較結果をスタックに積む

cmp だけでは、RAXに0や1は入らない。比較の状態は、CPU内部の「フラグ」という状態を記録するビットに残る。sete がその状態を見て、等しければ1、違えば0をALに書く。

ALは別のレジスタ領域ではなく、RAXの下位８ビットを指す名前。ALだけを書き換えても、RAXの残りの56ビットは以前のままなので、movzx でそこをゼロにする。これでRAX全体を、整数の0か1として使える。

図は「等しいか」の場合。大小比較では、sete の代わりに、調べたい条件に対応する命令を使う。比較の状態を見て0か1を作り、スタックに積むという流れは共通だ。

補足：大小比較で、作る命令の種類を減らす

a > b は b < a と同じ大小関係を調べる。> と >= のASTを、左右を交換した < と <= の木に直せば、命令生成を共用できる。ここでは、式の値が評価順序に影響されない、この電卓言語の範囲を扱う。

比較まで含めた文法を見渡す

04で加減算を担当していた規則を add と呼び、式全体の入り口 expr から比較の規則を呼ぶようにする。equality は等しい・等しくないの比較、relational は大小比較、unary は単項の符号を担当する。

expr       = equality
equality   = relational (("==" | "!=") relational)*
relational = add (("<" | "<=" | ">" | ">=") add)*
add        = mul (("+" | "-") mul)*
mul        = unary (("*" | "/") unary)*
unary      = ("+" | "-")? primary
primary    = num | "(" expr ")"

? は０回か１回。下の層ほど強く結びつく。1 + 2 < 4 は (1 + 2) < 4 と読まれる。等値・大小比較も左結合で、数学の連鎖比較とは異なる。

08理解を確かめる

  
確認するのは、出力した文字だけではない

  
実装の確認では、入力を自作コンパイラに渡し、出力したアセンブリをアセンブル・リンクして、できた実行ファイルの結果を確かめる。make はビルドを繰り返せる形にし、テストは機能を追加したときに以前の式が壊れていないか確かめる役割を持つ。

  
式の計算結果と、シェルで見る終了ステータスは区別する。Unixの終了ステータスとして観察できるのは下位８ビットなので、256は0、−1は255になる。原書のテストでは、式全体の結果を0〜255に収めると比較しやすい。観察欄は計算結果そのものと、下位８ビットの両方を表示する。

  
トークナイザは「掛け算が先」と決める？
数と記号に区切るところまで。演算のまとまりを文法に従ってASTにするのはパーサ。生成器は、その木が示す構造に沿ってコードを出す。

  
スタックから右の値が先に出るのはなぜ？
生成器が左の式、右の式の順で結果を積むから。後から積んだ右が先に出る。引き算では「先に出た値から引く」と逆の計算になる。

  
最後の pop rax を忘れると、なぜ困る？
返り値をRAXに置けず、計算結果がスタックに残る。直後のretはその計算結果を戻り先として取り出してしまう。生成コードは式の結果を取り出し、スタックを元の深さに戻す必要がある。

  
cmp の直後、RAXはもう0か1になっている？
まだ。cmpは比較の状態をフラグに残す。条件に応じてALを0か1にし、それをRAX全体へゼロ拡張してから、整数として扱える。

  
1 < 2 < 1 は、数学と同じように読める？
この文法では左結合なので、(1 < 2) < 1 → 1 < 1 → 0。２つの比較を同時に満たすか、という数学の読み方ではない。

  
どんな入力をテストに入れると、読み違いに気づける？
優先順位とカッコ、左結合の減算、空白を含む式、負の割り算、真と偽の比較、そして数の欠落や閉じカッコの不足。正しい式が動くことと、不正な式が拒否されることの両方を確認する。
